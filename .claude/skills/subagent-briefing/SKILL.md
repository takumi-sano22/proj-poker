# Subagent Briefing Policy

subagent を起動するときの **prompt（入力）と戻り値（出力）の設計規律**。
目的は、親の会話コンテキストやファイル全文を子へ丸投げして、トークンとコンテキストを浪費するのを防ぐこと。

## 前提（仕組み）

- subagent は **親の会話履歴を自動では引き継がない**。子が初回に受け取るのは「親が `prompt` に書いた文字列」＋「agent type の system prompt」だけ。
- したがってトークン過剰の原因は自動引き継ぎではなく、次の2つ。**この skill はこの2つを両方抑える。**
  1. **入力肥大**：親が `prompt` に会話履歴・ファイル全文・冗長な背景を貼り込む。
  2. **出力肥大**：子の戻り値（最終メッセージ）が長文・ファイルダンプで返り、親のコンテキストを膨らませる。

## 棲み分け

- **誰に渡すか**（Haiku/Sonnet/Opus の選択、Explore へ委譲するか）は `model-selection` skill に従う。
- 本 skill は **何を渡すか／何を返させるか** だけを扱う。委譲先の判断は重複させない。

## 委譲先の名前付きエージェント（プロジェクト定義・`.claude/agents/`）

作業種別ごとに **model を固定した名前付きエージェント**を用意している。委譲時は `agentType`（Agent ツール）でこれを選ぶと、都度の `model:` 指定に頼らず構造的に下位モデルへ振り分けられる（`general-purpose` は本体モデル＝Opus を継承しコストが下がらないため、下記に当てはまる作業は名前付きエージェントを優先する）。

| 作業種別 | エージェント | model | 補足 |
|----------|--------------|-------|------|
| **1 Issue の merge-ready までの所有** | **`issue-worker`** | sonnet / effort high（重い Issue は Agent ツールの `model` 引数に `opus`） | worktree 作成・ガイダンス読込・実装・検証・commit / push / PR・自己レビュー・Codex・Capture まで自分で進め、**compact status か `NEEDS_HUMAN` だけ**を返す。**最終マージはさせない**（hook も deny）。渡すものは下記「Issue Worker へ渡すもの」 |
| 設計が確定した定型実装・小〜中リファクタ・テスト追加 | `impl` | sonnet | 方針は親が決め、実装だけ任せる。設計判断・権限/課金/セキュリティは対象外。**該当する `implementation-guidance/references/<領域>.md` の絶対パスを「対象」に書いて渡す**（内容は貼らない） |
| 機械的・低リスク（ログ/diff確認・定型grep・整形・同型の一括変更） | `chore` | haiku | 判断が絡んだら停止して親に戻す。**読み取り中心の探索は `Explore`** |
| PR/コミット前の差分レビュー | `reviewer` | opus / effort high | **読み取り専用（`tools: Read, Grep, Glob`＝Bash も無し）**。差分は親が `git diff` を保存して渡し、reviewer は Read で読む。findings だけ返し修正・マージはしない。**必須入力 4 点（パッチ絶対パス・対象ルート絶対パス・差分クラス・台帳/チェックリストの絶対パス一覧）が欠けると fail-closed で止まる**（一次情報は `.claude/agents/reviewer.md`「入力」） |

- いずれも親の会話履歴・skill を引き継がない。**このテンプレートの入力（タスク・対象 path:line・確定値・制約・出力形式）を必ず渡す**。
- エスカレーション条件（判断が必要・2回失敗・範囲拡大・セキュリティ影響）で子が止まったら、親（Opus）が引き取る（`model-selection` skill）。

## Issue Worker へ渡すもの

Worker は `github-workflow` 固有版と各 skill を自分で Read するため、手順を書き写さない。渡すのは次だけ:

```
## タスク
Issue #<N> を merge-ready まで進める（マージはしない）

## 入力
- Issue 番号: #<N>
- リポジトリルート（絶対パス）: /home/ai/project/proj-poker
- ブランチ名: feature/<N>-<short-name>（worktree は .claude/worktrees/<branch>）
- 触ってはいけない領域: <パスや領域。無ければ「なし」>
- 追加の制約: <確定値・命名・並行中の他 Issue との境界>
- 実装前ガイダンス（絶対パス）: /home/ai/project/proj-poker/.claude/skills/implementation-guidance/references/<領域>.md

## 返す出力
compact status（ISSUE / PR / HEAD / STATE / TEST / REVIEW2 / LEARNING / HUMAN_DECISION）または NEEDS_HUMAN。patch・生ログ・第 2 段レビュー（Codex / reviewer）の全文は返さない。
```

再開（handoff）では **PR 番号・branch・既存 worktree の絶対パス・現 HEAD** を渡し、新規 worktree を作らせない。

## 入力テンプレート（親→子の prompt）

会話履歴やファイル全文は貼らず、この骨格に最小限だけ詰める。

```
## タスク
<1〜2文。何をしてほしいか>

## 対象（全文は貼らない・子に読ませる）
- 読むべき場所: path/to/file.ts:120-160
- 探索の起点: <シンボル名 / キーワード>
- 実装前ガイダンス（impl へ委譲時）: /abs/path/.claude/skills/implementation-guidance/references/<領域>.md
- 台帳・チェックリスト（reviewer へ委譲時）: /abs/path/.claude/skills/code-review/references/learned-checks.md ほか

## ゴール / 完了条件
<何が返れば成功か>

## 制約（子の読み込み・往復を縛る ＝ 最大のトークン源）
- 読む範囲は上記の対象に限定。指定範囲外は読まない・触らない。
- 探索の広さに上限を置く（例: 確認は最大 N ファイル / これ以上は広げず報告）。
- ツール往復をだらだら続けない。分かった時点で打ち切って返す。

## 返す出力（これ以外は返さない）
<項目・構造を指定。ファイル全文 / 長い引用は禁止>
```

> **子の内部ループ（ファイル読み・ツール往復）が最大のトークン源**。入力 prompt を絞っても、子が無制限に読み回れば意味がない。「読む範囲」と「広さ・往復の上限」を必ず明示する。

## 出力規律（子→親）

戻り値の量を縛る。手段は2段階で、定型データなら schema を第一手にする。

**① 定型データを集める場合 → `schema` で型固定（第一手）**

prose の「簡潔に」より、Agent / Workflow の構造化出力（`schema`）で返す型を機械的に縛る方が確実。
返す項目が決まっている調査・列挙・判定はこちらを優先する。

**② 自由記述で返させる場合 → prompt 末尾に定型ルールを付与**

```
出力ルール:
- 結論ファースト。根拠は要約のみ。
- コードは file:line 参照＋最小抜粋にする。ファイル全文ダンプは禁止。
- 箇条書き / 表で簡潔に。前置き・謝辞・経緯の説明は不要。
```

## 起動前チェック（毎回）

1. **会話履歴を貼っていないか** → 貼らず「子に読ませる」、必要なら 2〜3 行に要約して渡す。
2. **ファイル全文を貼っていないか** → `path:line` で位置だけ渡し、本文は子に読ませる。
3. **子の読む範囲・往復に上限を置いたか**（最大のトークン源）→ 読む対象とファイル数・探索の広さを明示し、無制限に読み回らせない。
4. **出力形式を指定したか** → 定型データなら `schema` を第一手に。自由記述なら「返す出力」と末尾の出力ルールを付ける。
5. **そもそも委譲が要るか** → 1〜2 ファイルの単純確認など、親が直接やった方が安いなら委譲しない（子は system prompt とツール定義を丸ごと再展開するため、軽い作業は逆に高くつく）。

## やりがちな失敗

- 「念のため」と会話の経緯を丸ごと貼る → 子は判断に使わない。タスクとゴールだけで足りる。
- 子に「調べて報告して」とだけ頼む → 戻り値が青天井になる。**返す形と量を必ず指定する。**
- 親で読んだファイル本文を子にも貼る → 二重保持。位置参照だけ渡し、必要な子に読ませる。

## 一言ルール

- 入力は **タスク・対象（path:line）・ゴール・出力形式** の4点だけ。
- 出力は **結論ファースト＋最小抜粋**。全文ダンプ禁止。
- 履歴とファイル全文は **貼らずに読ませる**。
