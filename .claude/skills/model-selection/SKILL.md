# Model Selection Policy

## 基本方針（本体ループ）

- **本体ループは Opus 固定**。タスクごとに `/model` でティアを切り替える運用は行わない。
- **コスト最適化の主手段はサブエージェント委譲**。探索・大量ファイル走査・定型実装を子エージェントに委譲し、親の Opus がコンテキストを節約して判断に集中できるようにする。
- **Fable 5 は特例利用**（後述）。通常セッションの既定は Opus。

> **根拠**: 実際の利用ログでは本体ループ Opus 100%・統合でも Opus 94.1% と、旧方針「既定 Sonnet」と実態が乖離していた。方針を実態に合わせ、コスト最適化はモデル切替よりサブ委譲で行う構造に再定義する。

## モデルの位置づけ

4 ティア構成（低位 → 高位）:

| ティア | エイリアス | 主な用途 |
|--------|------------|---------|
| Haiku | `haiku` | 機械的・低リスク・大量の調査・探索（サブエージェント中心） |
| Sonnet | `sonnet` | 設計が定まった定型実装・テスト追加（サブエージェント中心） |
| Opus | `opus` | **本体ループの既定**。設計判断・アーキテクチャ・セキュリティ・レビュー |
| Fable 5 | `fable` / `best` | Opus 上位。長時間・大規模・曖昧な問題向けの特例モデル |

> **具体的なモデルIDは環境依存で陳腐化する**。各ティアとも常に**最新世代**を使う。参考（執筆時点）: Fable 5 / Opus 4.8 / Sonnet 5 / Haiku 4.5。

## 各ティアで行う作業

### Haiku（機械的・低リスク・大量 → サブエージェント専用）

判断をほぼ伴わず、間違えても容易に気づけて影響が小さい作業。**本体では直接使わず、サブエージェント（`Explore` 等）を通じて使う。**

- ログ / diff / ファイル内容の確認・要約
- 定型的な grep・検索結果の整理・一覧化
- フォーマット・自明な lint 修正
- 大量ファイルへの同型の機械的変更

> 判断（どう直すか・どれが正しいか）が絡んだ時点で Sonnet へ上げる。

### Sonnet（設計が定まった実装 → サブエージェント専用）

設計が確定した上で手を動かす、標準的な開発作業。**本体での切替ではなく、サブエージェント（`general-purpose` / `Plan` 等）として使う。**

- 既存設計に沿った実装
- 小さな機能追加・テスト追加
- 既存パターンに沿ったバグ修正
- Opus が作成した計画に沿った実装

### Opus（本体ループの既定）

方針を決める・または間違えると取り返しがつきにくい作業。**本体ループでこれを行う。**

- 実装方針・設計方針の比較判断
- アーキテクチャ・API・DB・ディレクトリ構成の決定
- 認証・認可・Secrets・Token・権限設計
- Poker ドメインの不変条件に触れる設計（情報分離・KnowledgeState・Hindsight Leak・Event Log 正本・`decision_log.yaml` の判断との整合）
- Terraform・CI/CD・インフラ・課金リソース
- 破壊的変更、データ削除、replace / destroy が発生しうる作業
- 変更範囲が広く、既存仕様への影響が読みにくい
- 原因不明・再現不安定なバグの調査
- PR前の設計・影響範囲・セキュリティレビュー

## Fable 5 の使い方（特例利用）

[公式仕様](https://code.claude.com/docs/en/model-config.md) より:

> "Fable 5 is the most capable model in Claude Code, suited to tasks larger than a single sitting. It sustains long autonomous sessions, investigates before acting, and verifies its work more often than smaller models."

**向いているケース**:
- 根本原因調査・障害デバッグ・アーキテクチャ決定など、調査→行動→検証を長く繰り返すタスク
- 通常なら複数セッション / 複数 Issue に分割するような大規模作業
- 手順より「達成すべき結果」を伝えるほうが効果的な曖昧な問題

**向いていないケース（Opus で十分）**:
- 通常の実装タスク
- サイバーセキュリティ・生物学分野（セーフガードで Opus 自動フォールバックが発生）
- Zero Data Retention 環境（利用不可）

**選択方法**: `/model fable` または `/model best`（Fable 5 が利用可能な場合に最上位を選ぶ）

> Fable 5 はどのアカウントタイプでもデフォルトではない。明示的に `/model fable` を実行した場合のみ起動する。

## effort レベル（Fable 5 / Opus 4.8 以降）

本体が Opus または Fable 5 の場合、`/effort` で推論深度を調整できる。

| レベル | 使い分け |
|--------|----------|
| `low` | 短い・スコープが狭い・レイテンシ優先タスク |
| `medium` | コスト優先で知性を多少犠牲にしてよいケース |
| `high` | **デフォルト**。ほとんどのコーディングタスクに適切 |
| `xhigh` | 深い推論が必要なケース（Opus 4.7 のデフォルト） |
| `max` | 最高の推論。セッション限定（設定ファイルへの保存不可）。過剰推論になりやすいため多用しない |

> effort はモデルごとにキャリブレーションが異なるため、同じレベル名でも絶対量は異なる。普段は `high`（デフォルト）のまま使い、必要時のみ調整する。

## サブエージェント委譲の指針

コスト最適化の主手段。**本体 Opus で判断し、作業は子エージェントに逃がす**構造を基本とする。

| 作業種別 | 推奨ティア | 手段 |
|----------|------------|------|
| 読み取り中心の探索・検索 | Haiku | `Explore` エージェント |
| 多段・複雑な調査 | Sonnet | `general-purpose` / `Plan` |
| 機械的な fan-out（定型変更・フォーマット等） | Haiku | Agent（frontmatter `model: haiku`） |
| **1 Issue の merge-ready までの所有**（完全自走・複数 Issue の既定） | Sonnet（設計判断・複数領域・高 blast radius なら Opus を起動時に上書き） | `issue-worker` エージェント（マージは親） |
| 設計が定まった実装 | Sonnet | Agent（frontmatter `model: sonnet`） |
| 設計判断・レビュー | Opus | 本体で行う |

- **委譲時の注意**: 何を渡すか／何を返させるかは `subagent-briefing` skill に従う。会話履歴やファイル全文を丸ごと渡さない。
- サブエージェントの frontmatter `model:` フィールドでティアを個別指定できる（`CLAUDE_CODE_SUBAGENT_MODEL` 環境変数で統一指定も可）。**起動ごとの上書きは Agent ツールの `model` 引数**（frontmatter より優先。`issue-worker` を重い Issue で Opus にするときに使う）。

## エスカレーション条件

サブエージェント（Haiku / Sonnet）が以下に該当したら作業を止めて親（Opus）に戻す:

- 機械的と思ったが判断が必要になった
- 方針が複数あり優劣を判断できない
- 同じ修正で2回失敗した / エラー原因の説明が一貫しない
- 変更範囲が想定より広がった
- セキュリティ・権限・課金への影響が見えた

本体（Opus）で設計の根本変更・要件の曖昧さが発生した → ユーザーに確認して止まる。

## 既知問題: Opus 4.8 の暴走 thinking（長考ハング）

Opus 4.8 は adaptive thinking の既知問題（anthropics/claude-code#64153 / #26171 相当）により、**ツール実行直後の次ターンで不可視 thinking だけを output 上限まで生成し、8分〜十数分「考えたまま止まって見える」**ことがある（実測: 2026-07-01〜07-08 に7事案・最長3連続で約50分）。CLI 側に検出・中断機構は無く、根本修正は未リリース。

- **見分け方**: 直前のツール実行は一瞬で完了しているのに、その後 **5分以上**テキストもツール呼び出しも出ずスピナーだけが回る。
- **ユーザーの即時対処**: **待たずに Esc で中断して再指示**する。多くは次のリクエストで正常回復する（中断してもコンテキストは失われない）。
- **リポジトリ側ガード**: `.claude/settings.json` の `env.CLAUDE_CODE_MAX_OUTPUT_TOKENS=32000` で1リクエストの暴走上限を半減している（64k→32k。正常ターンが 32k を超えるのは稀＝5週間で4件で、上限到達時もハーネスが自動継続する）。`MAX_THINKING_TOKENS` は adaptive thinking モデルで 400 エラー報告があるため使わない。
- この症状は**モデル側要因**であり、MCP・hooks・サブエージェントのハングとは別物（それらは transcript 分析で発生ゼロを確認済み）。頻発してセッションにならない場合のみ、一時的に `/model sonnet` へ退避するか Fable 5 特例を検討する。

## 自走中の注意

- 外部レビューの細かい指摘が無限に出るケースは、ティアを上げて押し切るより follow-up Issue に切り出して確定する。
- **Fable 5 や `max` effort は意図的に選ぶ場合のみ**。普段は Opus + `high`（デフォルト）で十分。

## 一言ルール

- 本体ループは **Opus 固定**。切替なし。
- コスト最適化は**サブエージェント委譲**（Haiku / Sonnet）。
- 長時間・大規模・曖昧な問題は **Fable 5**（特例）。
- effort は普段 **high**（デフォルト）。深い推論が必要なら **xhigh**、一発勝負は **max**。
