# task-log Skill

## 目的

Claude Codeが行った作業を、後からエンジニアが追えるようにする。

## 手順

1. 作業開始時に `docs/taskLog/` を確認する。
2. 関連する作業ログがなければ、新規ファイルを作成する。
3. ファイル名は `issue-<GitHub Issue番号>-<短い説明>.md` とする（例: `issue-3-claude-assets.md`）。Issue に紐づかない作業のみ `YYYYMMDD-<短い説明>.md` とする。
4. 実装前に、概要・初期調査・設計方針を記録する。
5. 実装後に、変更ファイル・実行コマンド・テスト結果・残課題を記録する。
6. 曖昧な記述を避け、何をなぜ変更したかを書く。

## 注意点

- 実際に実行していないテストを「成功」と書かない。
- 変更していないファイルを変更済みとして書かない。
- 「修正した」だけで終わらせず、具体的に書く。
