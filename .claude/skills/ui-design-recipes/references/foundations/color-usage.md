# 色の使い方（役割・段・グラデーション・散らし方）

> **いつ読むか**: 配色を決める／グラデーションをかける／アクセントを置く／ブランド色を差し替えるとき
> **前提**: なし（foundations の起点）
> **この reference に HEX 値は無い。** 色そのものはプロジェクトのベースライン色で決まる。
> ここに書くのは「どの役割に・どの段を・どう組み合わせるか」の規則だけ。

## 1. 要点

- 色は**役割名**で持つ（`brand` / `accent` / `ink` / `surface` / `on-surface` …）。色相名を使わない。
- 有彩色は **brand（主）と accent（隣接色相の副）の 2 本**が基本。専用の役割が要るときだけ別の色相を足す。
- ニュートラル（`ink`）は無彩色の灰にせず、**本文色と同じ色相へ寄せる**。
- **白文字を載せる塗りは、白文字が 4.5:1 以上になる段から**（ブランド系は一般に 600 以降、状態色は 700）。
- グラデーションは**明度差＋色相移動**でかける。面は 180deg（上が明るい）、塗りは 135deg（左上→右下）。
- 濃い塗りは**常時表示で 1 画面 4 種類まで**、淡い面グラデは **1 か所**、それ以外のアクセントは**線と点だけ**。

## 2. 役割の体系（何色を持つか）

| 役割 | 段 | 使う場所 | 使わない場所 |
| --- | --- | --- | --- |
| `brand` | 50〜900 | 主要な導線（主ボタン・リンク・選択中・フォーカス） | — |
| `accent` | 50〜900 | グラデーションの下端・強調バッジ・主役（アバター・マスコット等）周辺の装飾 | **主要導線の単独色**（brand と張り合うと、どちらが押すものか分からなくなる） |
| `ink`（ニュートラル） | 50〜900 | 本文・補助文字・区切り線・沈めた面 | — |
| 状態 `success` / `warning` / `danger` | 50 / 500 / 600 / 700 | 状態の表示だけ | **装飾への流用**（「赤＝危険」の約束が崩れる）。例外は 2 つだけ: 状態とは別名のトークンに切り出す／最も淡い段（50）を**面だけ**借りて文字は通常色のまま（本物の状態表示と並ぶ場所では借りない） |
| 専用色相（任意） | 50〜900 | 「会話ではなくこちらから差し出す候補」「開発元への報告」「読むだけの補足」など、**他の面と別物だと色で伝えたい役割** | 主要導線 |

**役割エイリアス**（画面側はこちらを使う。段を直接指すのは「hover で 1 段濃くする」など段そのものに意味があるときだけ）:

| エイリアス | 参照先 | 役割 |
| --- | --- | --- |
| `surface` | ほぼ白（brand 寄りに極わずか色づけ） | 画面の地 |
| `surface-raised` | 白 | 地から持ち上げた面（カード・吹き出し・パネル・モーダル） |
| `surface-sunken` | `ink-100` | 地に沈めた面（入力欄・コード面・脇役の面） |
| `surface-brand` | `brand-50` | ブランド寄りの淡い面（選択中・強調パネル・hover の面） |
| `scrim` | `ink-900` の 45% | モーダル背後の覆い（**黒を使わない**） |
| `on-surface` | `ink-900` | 本文 |
| `on-surface-muted` | `ink-600` | 副次テキスト・ラベル |
| `on-surface-subtle` | `ink-500` | 補助テキスト・プレースホルダ |
| `on-surface-disabled` | `ink-400` | 無効状態（コントラスト要件の免除対象） |
| `on-brand` | 白 | brand / accent / 状態色の塗りに載せる文字 |
| `border` | `ink-200` | 区切り線（**装飾専用**。操作要素の輪郭に使わない） |
| `border-strong` | `ink-300` | 強めの区切り・カードや別レイヤーの縁 |
| `border-interactive` | `ink-400` | 不透明な面の上の操作要素の輪郭（3:1 を確保） |
| `border-interactive-glass` | `ink-500` | 半透明の面の上の操作要素の輪郭（1 段濃くしないと 3:1 を割る） |
| `focus` | `brand-500` | フォーカスリング（必ず offset を付けて地の上に出す） |

**なぜ役割名か**: ①ブランドを差し替えても値の入れ替えだけで済む ②ダークモードを足すときも値の再定義だけで済む
（`white` / `gray-900` と書いていると名前の付け替えから始まる） ③画面側が色相を知らない状態を保てる。

## 3. 段（50〜900）の使い分け

brand・accent・専用色相は同じ段構成にし、**同じ段に同じ意味を持たせる**。こうすると
「境界は 200、文字は 700」のような規則を色相をまたいでそのまま使える。

| 段 | 役割 | 補足 |
| --- | --- | --- |
| 50 | 淡い面（選択中・強調パネル・hover の面） | `surface-brand` の参照先 |
| 100 | 淡い面の濃いめ・面グラデの暗端 | 暗端に使えるのは相対輝度 0.80 以上の段だけ（§5） |
| 200 | 境界（装飾の縁・面の輪郭） | 操作要素の輪郭には使わない |
| 300 | 装飾・アイコンの丸枠 | 隣の役割の 200 と見分けが付く濃さを残す |
| 400 | 装飾・アイコン・装飾光 | |
| 500 | **アンカー（明）**: フォーカスリング・入力欄のリング・グラデーションの上端 | **白文字を載せる塗りには使わない**（ブランド系は多くの場合 4.5:1 をわずかに割る） |
| 600 | **アンカー**: 主ボタンの静止色 | 白文字を載せられる最初の段（実測で確認する） |
| 700 | 主ボタンの hover・リンク文字・専用色相の文字色 | hover は「持ち上げ＋わずかに濃く」 |
| 800 | 淡い面や半透明の面の上の強い文字 | 半透明面では 700 が割れることがある |
| 900 | 最も濃い段・選択中の文字 | |

**状態色は 50 / 500 / 600 / 700 だけ持ち、白文字を載せる塗りは 700 に統一する。**
600 は success・warning で AA を割ることが多く、色ごとに段を変えるより 700 に揃える方が規則として憶えやすい。

## 4. ベースライン色から段を作る手順

1. **アンカーを 2 色決める**（主ボタンの色＝600、それより明るいリング用＝500）。人間と合意して固定する。
2. **2 色をちょうど含む色相ランプで 50〜900 を補完する。** 独自に 1 段ずつ引くより等歩度が保たれ、破綻しにくい。
3. **accent はブランドの隣接色相**で同じ段構成を作る（アンカーは 500）。
4. **ink は本文色（900）の色相でランプを作る。** 無彩色の灰を混ぜると、ブランド面の中で借り物の灰色に見える。
5. **実測して段をずらす。** 素のランプのままだと `ink-400`（輪郭）が 3:1、`ink-500`（補助文字）が
   沈めた面の上で 4.5:1 を割りやすい。割ったら暗い側へ値を調整する（手順は `contrast-and-a11y.md`）。
6. **「白文字を載せる最初の段」を実測で確定し、規則として書く**（例: 「塗り＋白文字は 600 以降」）。
7. `surface` は白に brand をごくわずかに混ぜた色にする（純白の `surface-raised` との段差を作るため・§5 の地）。

**段が足りないとき**（例: 50 よりさらに淡い面が欲しい）は新しい段を作らず、
`color-mix(in srgb, var(--color-brand-50) 50%, #fff)` のように**既存の段と白を混ぜて**導出する。
値を直書きしない規律を保ったまま、ランプを増やさずに済む。

## 5. グラデーションのかけ方

### 5.1 原則

- **明度差だけで強めない。色相移動を併用する。** 明度差だけで強めるとコントラストの余力を食う。
  色相の変化は同じ余力でも目に拾われやすい。
- **向きで役割を分ける。** 面（読む・置く面）は **180deg**（上が明るい＝光源が上）。
  塗り（押す・主張する面）は **135deg**（左上→右下）。
- **制約は段名ではなく実測値で書く。**
  - 面グラデの暗端: **相対輝度 0.80 以上**。補助テキスト（`ink-500`）が 4.5:1 を保つ下限が約 0.795、
    操作要素の輪郭（`ink-400`）が 3:1 を保つ下限が約 0.769 で、厳しい方を切り上げた値。
    ランプを差し替えたら、同じ式で下限を計算し直す。
  - 塗りグラデの端: **載せる白文字が 4.5:1 以上**。段名で「600 より明るい段を置かない」と書くと、
    隣接色相の 700 のように段名では違反に見えて実測では満たす段を誤って禁じる。
- **明るい側の端を固定し、余地のある端だけ動かす。** 塗りの上端は白文字の下限なので動かせない。
  色幅を弱めたいときは下端を 1 段明るくする。
- **グラデーションをゼロにしない。** 「強すぎる」と言われたら暗端を弱める（`color-mix` で白に寄せる）。
  単色にすると立体感が消える。

### 5.2 レシピ

| 名前 | 向き | 上端 → 下端 | 用途 | 規律 |
| --- | --- | --- | --- | --- |
| 地（page） | 165deg | `surface` 0% → `ink-50` 55% → `brand-50` 100% | `body` の背景だけ | 画面側で当て直さない。1024px 未満は停止位置を 0 / 20 / 60% へ前倒し（縦長の画面だと可視域がほぼ白になるため） |
| 面 | 180deg | 白 → `brand-100` | 面のレシピ（L1〜L4）に当てはまらない明るい面（認証画面のカード・一覧の器など） | 暗端は相対輝度 0.80 以上。**層が決まる面には使わず面のレシピを優先する**（吹き出し・脇役・モーダルを全部これで塗ると区別が消える） |
| 面（弱） | 180deg | 白 → `brand-50` と白の 50:50 | 「まだ強い」と言われた面 | 新しい段を作らず混色で導出 |
| 沈めた面 | 180deg | `brand-100` → `ink-50` | 非選択のピル・コード面の枠 | |
| 読む対象（相手の発言） | 180deg | `brand-50` → `brand-100` | 会話の吹き出し | 「ぎりぎり単色ではない」程度。輪郭は縁（`brand-200`）に任せる |
| 塗り | 135deg | `brand-600` → `accent-800` | 選択中のピル・セグメントの選択側 | 白文字 4.5:1 を両端で |
| CTA | 135deg | `brand-600` → `accent-900` | 送信・主ボタン | 同上。hover でグラデを切り替えない（影で示す） |
| 自分の発言 | 135deg | `brand-600` → `accent-700` | 自分の吹き出し | 塗りより色幅を弱める（読む面なので主張を抑える） |
| 淡い強調 | 135deg | `brand-50` → `accent-100` | 主役（アバター・キャラクター等）の名前やセリフを置く帯 | **1 画面 1 か所** |
| 入力欄のリング | 135deg | `brand-500` → `accent-500`（フォーカス時 600 → 600） | 入力欄の 2px の縁 | 輪郭として 3:1 が要る。300 段は割る |
| 専用色相の面 | 180deg | 白に近い専用色 → `<hue>-100`（60%）→ 少し濃い専用色 | 差し出す候補など | 会話の面と同じ「上が明るい」構造にし、色相だけ変える |
| 専用色相の読み物 | 180deg | ほぼ白 → `<hue>-50`（55%）→ `<hue>-100` | 使い方パネルなど | 彩度をさらに落とす（操作の主役ではない） |

**半透明の面に使う版**は、各停止点に `color-mix(in srgb, <色> 90%, transparent)` のように
アルファを載せた**別のトークン**を持つ。不透明前提のトークンを半透明の面に流用すると、アルファが失われて背景を覆ってしまう。

## 6. 色の散らし方（出現の上限・置き場所）

「明るい色をどこに何回出すか」を決めないと、強さを配り直しても再び平板になる。

| 規律 | 上限 |
| --- | --- |
| **A. 濃い塗り**（CTA・塗りのグラデ・`brand-600`） | 常時表示の面で **1 画面 4 種類まで**。同じレシピの繰り返し（自分の吹き出しが何個も並ぶ等）は 1 種類と数える |
| **A'. 一時的な面** | 出ている間だけ 5 種類目になってよい。ただし濃くしてよいのは**いま操作を求めている主操作 1 つだけ**（拒否側は濃くしない） |
| **B. 淡い面グラデ**（淡い強調） | **1 画面 1 か所** |
| **C. それ以外のアクセント** | **線と点だけ**（幅 2〜3px の縦線・直径 12px 以下のドット・アイコンの色）。面を塗らない |
| **D. 脇役の面・別レイヤーの内側** | 濃い塗りを置かない（主役が霞む）。CTA はモーダル等の footer にだけ置いてよい |

**置き場所の作法**:

- **選択待ちの面**（「どれにしますか？」と操作を求める面）は、色相を brand から accent へ振って会話の面から切り離す。
- **専用色相の決め方**: 隣接する役割との色相の距離で決める。赤（`danger`）と読み違えられない側に寄せる。
  主張させたくない読み物は彩度を落とし、50〜200 を面・700 を文字にする。
  実機で見て「強すぎる／薄すぎる」を往復する前提で、**毎回少しずつ**動かす（大きく振ると反対側に振れすぎる）。
- **発光・注意を引く色**は、画面のどの面とも色相が離れた色にする。ブランドや隣の面と同系色だと光っても埋もれる。
- **影と scrim は `ink-900` を透かす。** 純黒を重ねるとブランド面から浮いた灰色になる。
- **表示モードの差（不透明な面の画面と背景を透かす面の画面、将来のダークモード）は色相で出さない。** 面の作り方（不透明／半透明）で出す。
  色相で分けた瞬間に、ブランドの差し替えが 2 系統になる。
- **本人に向ける状態表示に「危険」と読める色を使わない**（プロダクトの倫理要件がある場合）。
  赤は破壊操作と入力エラーに限る。
- **構文ハイライトは役割トークンと別の独立パレット**にする（状態色を流用すると意味が壊れる）。

## 7. 実装の雛形（Tailwind v4 / 素の CSS）

Tailwind v4 は設定ファイルを持たず、`@theme` に書いたカスタムプロパティがそのままユーティリティになる
（`--color-brand-600` → `bg-brand-600`、`--background-image-cta-gradient` → `bg-cta-gradient`）。
`static` を付けると未参照の変数も出力される（段を先に全部用意し、参照側が後から来る場合に要る）。

```css
@import "tailwindcss";

@theme static {
  /* ブランド（アンカーは 600 / 500。間は色相ランプで補完）。値はプロジェクトごとに入れる */
  --color-brand-50: <値>;   /* …900 まで同じ形 */
  --color-brand-500: <アンカー明>;
  --color-brand-600: <アンカー>;
  /* accent / ink / 状態色 / 専用色相も同じ段構成 */

  /* 役割エイリアス（画面側はこちらを使う） */
  --color-surface: <白に brand をごくわずか混ぜた色>;
  --color-surface-raised: #ffffff;
  --color-surface-sunken: var(--color-ink-100);
  --color-surface-brand: var(--color-brand-50);
  --color-scrim: color-mix(in srgb, var(--color-ink-900) 45%, transparent);
  --color-on-surface: var(--color-ink-900);
  --color-on-surface-muted: var(--color-ink-600);
  --color-on-surface-subtle: var(--color-ink-500);
  --color-on-surface-disabled: var(--color-ink-400);
  --color-on-brand: #ffffff;
  --color-border: var(--color-ink-200);
  --color-border-strong: var(--color-ink-300);
  --color-border-interactive: var(--color-ink-400);
  --color-border-interactive-glass: var(--color-ink-500);
  --color-focus: var(--color-brand-500);

  /* グラデーション（--background-image-* は bg-<name> になる） */
  --background-image-surface-gradient: linear-gradient(180deg, #ffffff 0%, var(--color-brand-100) 100%);
  --background-image-cta-gradient: linear-gradient(135deg, var(--color-brand-600) 0%, var(--color-accent-900) 100%);
  --background-image-brand-soft-gradient: linear-gradient(135deg, var(--color-brand-50) 0%, var(--color-accent-100) 100%);
  /* 半透明版は停止点ごとにアルファを載せた別トークンにする */
  --background-image-message-own-gradient-glass: linear-gradient(
    135deg,
    color-mix(in srgb, var(--color-brand-600) 90%, transparent) 0%,
    color-mix(in srgb, var(--color-accent-700) 90%, transparent) 100%
  );
}

/* 地は :root に置き、body だけが使う（画面側から参照しない） */
:root {
  --gradient-page: linear-gradient(165deg, var(--color-surface) 0%, var(--color-ink-50) 55%, var(--color-brand-50) 100%);
}
@media (max-width: 1023px) {
  :root {
    --gradient-page: linear-gradient(165deg, var(--color-surface) 0%, var(--color-ink-50) 20%, var(--color-brand-50) 60%);
  }
}
body {
  background: var(--gradient-page);
  color: var(--color-on-surface);
}
```

**Tailwind を使わない場合**は、`@theme static` を `:root` に読み替え、ユーティリティの代わりに
`background-image: var(--background-image-cta-gradient)` のように変数を直接参照する。

## 8. 落とし穴

- **段名で制約を書く**と、ランプを変えた瞬間に規則が嘘になる。相対輝度・コントラスト比で書く。
- **全部の面に同じレシピを当てる**と、吹き出し・メモ・モーダルが区別できなくなる（統一しすぎると安っぽく見える）。
  揃えるのは値ではなく「役割ごとに強さを配る規則」（`surface-and-depth.md` の面のレシピ）。
- **`border`（区切り線）を操作要素の輪郭に使う**と、地に対して 1.3:1 程度しかなく 3:1 を割る。
- **状態色を見出しや装飾に流用する**と、「緑＝成功」「赤＝危険」の意味が薄まる。どうしても流用するなら
  状態とは別名のトークンに切り出す（同じ値を指していても名前で意味を分ける）か、最も淡い段を面だけ借りて
  文字は通常色のままにする。**文字色まで状態色にすると、そのまま警告・成功の表示に見える。**

## 9. チェックリスト

- [ ] 新しく足した色は役割名で持ち、画面側で色相名・HEX を書いていない
- [ ] 白文字を載せた塗りは、最も不利な端で 4.5:1 以上（計算で確認した）
- [ ] 面グラデの暗端は相対輝度 0.80 以上（ランプを変えたなら下限を計算し直した）
- [ ] 濃い塗りは常時表示で 4 種類以内、淡い面グラデは 1 か所、それ以外のアクセントは線と点だけ
- [ ] 状態色を装飾に使っていない（使うなら別名トークンか、最も淡い段を面だけ借りて文字は通常色）
- [ ] 影・scrim に純黒を使っていない
- [ ] モード差を色相で出していない
