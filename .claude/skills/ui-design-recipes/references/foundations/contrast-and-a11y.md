# コントラストの実測・フォーカス・状態の示し方・キーボード

> **いつ読むか**: 色の組み合わせを確定するとき／半透明の面・グラデーションに文字を載せるとき／

> **前提**: `color-usage.md` の役割名
> 基準値（WCAG 2.1）と手順はそのまま再現してよい。

## 1. 要点

- **目視で判断しない。計算する。** 判定は保守的な計算値を正とし、実機のピクセル実測は裏取りに使う。
- 余裕のある値を採る。4.51:1 は採らず、**4.6〜4.8:1 の範囲で最も薄い値**を目安にする（環境差を吸収する）。
- **グラデーションは文字に最も不利な端で**、**半透明の面は実際に重なる背景のうち前景に最も不利なピクセルで**測る
  （暗い文字なら最も暗い背景、白文字など明るい前景なら最も明るい背景）。
- 制約は段名ではなく**相対輝度・コントラスト比**で書く（ランプを変えても規則が嘘にならない）。
- 状態（hover・選択・ON/OFF）は色の差だけで示さない。
- hover 前提の情報は hover / pointer の**能力**で出し分ける。

## 2. 基準と計算

| 対象 | 基準（AA） |
| --- | --- |
| 本文（通常サイズ） | 4.5:1 |
| 大きい文字（18pt / 14pt 太字以上） | 3:1 |
| 非テキスト（操作要素の輪郭・フォーカスリング・識別に必要な図形） | 3:1（WCAG 1.4.11） |
| 無効状態の文字・純粋な装飾 | 対象外 |

```js
// WCAG 2.1 の相対輝度とコントラスト比。半透明の面は over() で地に合成してから測る
const hex = (h) => h.replace("#", "").match(/../g).map((x) => parseInt(x, 16));
const lin = (c) => { c /= 255; return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4; };
const L = ([r, g, b]) => 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b);
const ratio = (a, b) => { const [x, y] = [L(a), L(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
const over = (fg, alpha, bg) => fg.map((c, i) => c * alpha + bg[i] * (1 - alpha)); // 地 bg の上に fg を alpha で重ねた実効色

// 例 1: 白 85% のパネルに暗い輪郭を載せる → 不利なのは最も暗い背景
const panel = over([255, 255, 255], 0.85, hex("<重なる領域の最暗ピクセル>"));
console.log(ratio(hex("<輪郭色>"), panel).toFixed(2));

// 例 2: 濃い色 90% の面に白文字を載せる → 不利なのは最も明るい背景
const bubble = over(hex("<塗りの色>"), 0.9, hex("<重なる領域の最明ピクセル>"));
console.log(ratio([255, 255, 255], bubble).toFixed(2));
```

- 使い捨てのスクリプトで測り、**測った値と組み合わせを設計書（トークンの一覧）に残す**。
  次に色を触る人が同じ計算をやり直さずに済み、どこが下限ぎりぎりかが分かる。
- 意匠を変えたら、変更後の値を測って Issue や PR に残す。

## 3. 何を地にして測るか

| 面 | 地にするもの |
| --- | --- |
| 不透明の単色 | その色 |
| グラデーション | **載せる文字に最も不利な端**（暗い文字なら暗端、白文字なら明るい端） |
| 半透明の面（背景画像・3D・動画の上） | **その UI が実際に重なる矩形に対応する背景領域のうち、前景に最も不利なピクセル**（暗い文字・暗い輪郭なら最暗、白文字など明るい前景なら最明）＋必ず載るオーバーレイ（ティント・scrim）を合成した色。暗い前景と明るい前景が同じ面に載るなら両方で測る |
| 半透明の面の上の、さらに半透明の面 | 下の面から順に合成した実効色 |

- **背景画像全体の最暗（最明）ピクセルでは測らない。** その UI が実際に重なる場所とは限らず、過度に保守的な数字になる
  （直しても直っていないように見える）。配置クラスと実寸からビューポート上の矩形を出し、`object-cover` の
  拡大率を逆算して、対応する領域だけを切り出して測る。縦横比で切り取られる範囲が変わるので、モバイル〜大画面の数点で回す。
- **必ず載るオーバーレイを地に含める。** 例えば白 85% のパネルを最暗の地に重ねるだけだと輪郭が 3:1 を割って見えても、
  背景に常に敷いてあるティントを含めると結果が変わる。含め忘れると、不要な値の変更をしてしまう。
- **ユーザー設定で透明度を下げられる場合**、保証するのは既定値でのコントラストに限る
  （下げたときの低下はユーザーの明示的な選択）。そのぶん、**重要な情報を半透明のレイヤーだけに置かない。**

## 4. 制約を実測基準で書く

**面グラデの暗端の下限**（例）を、載る要素から逆算する:

```
補助テキスト（相対輝度 Lt）が 4.5:1 を保つ地の下限:  Lbg ≥ 4.5 × (Lt + 0.05) − 0.05
操作要素の輪郭（相対輝度 Lb）が 3:1 を保つ地の下限:   Lbg ≥ 3   × (Lb + 0.05) − 0.05
→ 厳しい方を切り上げて「暗端は相対輝度 X 以上」と書く
```

補助テキストが相対輝度 0.1377、輪郭が 0.2230 の体系では、それぞれ 0.795 と 0.769 になり、「暗端は 0.80 以上」と書ける。
ランプを差し替えたら、この式で下限を計算し直す。

**白文字を載せる段**も同じ考え方で、「600 以降」という段名ではなく「白文字が 4.5:1 以上の段」と書いておき、
段名の規則はその実測の要約として添える。

**文字を薄くしたいとき**は、文字を薄くする前に**下地を整える**。見出しの文字色を薄くしたいなら、
文字の背後に淡い面（チップ）を敷けば、同じコントラストのまま文字を薄くできる。その際は**最も不利な経路を先に探す**
（チップを敷き忘れた 1 か所が、全体をそれ以上薄くできない足かせになる）。

## 5. 装飾の縁と操作の境界

- **区切り線（`border`）は装飾**で、3:1 は要らない。面の存在を伝えるだけの縁（カード・パネルの縁）も装飾。
- **操作要素の輪郭は識別を担うので 3:1 が要る**（`border-interactive`）。
- 縁が装飾か境界かは、**面どうしの差を測って**決める。入力欄の面とその下の面の差が 3:1 に遠く届かない（多くは 1.1〜1.2:1）なら、
  入力欄を入力欄と分からせているのは輪郭だけなので、輪郭に 3:1 が要る。
- **半透明の面の上では 1 段濃い輪郭**（`border-interactive-glass`）が要る。面が背景を透かして白より暗くなるため。
- 直したら**同じ語彙を横断して探す**。入力欄だけ直して、同じ淡い縁を使っている選択肢チップが残る、ということが起きる。
  見た目を関数・定数 1 か所に集約しておくと、次から散らない。

## 6. 状態を色だけで示さない

| 状態 | 示し方 |
| --- | --- |
| hover | 影を 1 段上げる（`rest` → `raise` / 主 CTA は `brand`）＋必要なら文字色 |
| active（押下） | 影を消す（`shadow-none`）＋持ち上げていたら戻す |
| 選択中 | **縁・文字色・影の 3 つ**（選択と非選択の面の差は 1.1:1 程度しか無い）。一瞬で分からせたいなら面を 1 段濃くするが、濃い塗りにはしない |
| ON / OFF（スイッチ） | つまみの位置＋トラックの色＋**「ON」「OFF」の文字** |
| 無効 | 透明度 60% ＋ `cursor-not-allowed`（文字はコントラスト要件の免除対象） |
| エラー | 赤の縁と文字＋**文言**（`role="alert"`） |

## 7. フォーカスリング

- 色の変化ではなく **`outline` 2px ＋ `outline-offset` 2px**。offset で地の上に出し、ボタン自身の塗りに埋もれさせない。
- フォーカス色（`focus`）は地に対して 3:1 以上。
- `* { outline-color: var(--color-focus) }` をグローバルに入れる（`motion.md` §5。遷移中にリングが白く消える問題を断つ）。
- 入力欄のリングを border ではなく背景で描くと、フォーカス時の outline と色が重ならず二重線にならない。

```tsx
"focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus"
```

## 8. hover 能力による出し分け

| 出したいもの | 条件 | Tailwind v4 |
| --- | --- | --- |
| キーボード操作のヒント・マウス専用の補足 | hover でき、ポインタが正確（マウス・トラックパッド） | `@custom-variant hover-fine (@media (hover: hover) and (pointer: fine));` → `hidden hover-fine:flex` |
| タッチでの常時ラベル（hover でしか出ないラベルの代わり） | hover できない | `hidden [@media(hover:none)]:inline` |
| ツールチップ | ポインタが正確なときだけ | `pointer-fine:group-hover:opacity-100` |

- **画面幅（`sm` / `md`）で代用しない。** 640px 以上のタッチ端末（タブレット）は hover も無く、幅条件の代替表示も出ない。
- **`aria-label` は見えるラベルの代わりにならない**（支援技術向け）。
- **hover でしか見えない情報を作らない。** 補足は常時表示し、hover は強調だけにする。

## 9. キーボード操作の割り当て条件

矢印キー・`?` などを document 側（グローバル）の操作へ割り当てるときの条件。

1. **フォーカス中の要素が次なら奪わない**: 編集可能要素（`input` / `textarea` / `[contenteditable]`）、
   操作要素（`button` / `a[href]` / `[role="button"]` / `select` / `tabindex` を持つ要素）、
   選択コントロール（radio group / `role="listbox"` の項目）。判定は画面の状態ではなく**フォーカス中の要素**で行う。
   - `←` `→` は入力欄から奪わない（文字カーソルの移動に必須）。
   - `↑` `↓` は **1 行の `<input>` に限り**奪ってよい。複数行の `<textarea>` と **IME 変換中**は奪わない
     （行の移動・変換候補の選択に使われる。日本語のプロダクトでは日常の操作）。
   - 操作要素（`button` 等）を除外するのは、**その要素の上でそのキーが別の意味を持つ**（選択肢間の移動・スライダーの増減など）から。
     モーダルのように閉じた範囲で、ボタン上のそのキーに他の意味が無いなら除外しなくてよい。除外すると、フォーカスが乗る要素が
     全部ボタンの画面ではそのキーが事実上効かなくなる（`components/modal.md` §4.3）。
2. **`event.defaultPrevented` が true なら降りる。** グローバル処理は bubble フェーズで登録し、ローカルが処理済みなら何もしない
   （capture で登録するとローカルより先に走ってしまう）。
3. **`Enter` をグローバルに割り当てない。** ボタンのネイティブなクリックと二重に発火する。
   「Enter で決定」とヒントに書くのはよい（ネイティブ動作の説明とグローバル処理の追加は別物）。
4. **キーヒントは 1〜3 と同じ条件で出す**（効かない状態でヒントを出さない）。表記は `kbd` 要素で統一する
   （12px・補助テキスト色・`radius-control` の細い枠）。**実装を読んで、実際に効くキーだけを書く。**

## 10. 落とし穴

- **背景画像全体の最暗ピクセルで測る**と、実際には重ならない場所の暗さで判定し、必要の無い値の変更をしてしまう。
  逆に**白文字の面を最暗の背景だけで測る**と、明るい背景（光・水面のハイライト等）の上で割れているのを見逃す。
  前景が暗いか明るいかで、不利な背景は逆になる。
  逆に**必ず載るオーバーレイ（ティント・scrim）を地に含め忘れる**と、半透明の面の上の輪郭が 3:1 を割って見える。
- **区切り線用の `border` を操作要素の輪郭に使う。** 地に対して 1.3:1 程度しかなく、WCAG 1.4.11 の 3:1 を割る。
- **直した組み合わせの隣を探さない。** 同じ淡い縁を使う別の部品（チップ・トグル等）が未修正のまま残る。
- **`aria-label` があるから見えるラベルは要らない、と判断する。** 支援技術向けの名前であって、画面上の説明の代わりにならない。
- **グローバルな `Enter` の割り当て**は、ボタンのネイティブなクリックと二重に発火する。
- **4.51:1 のような境界ぎりぎりの値を採る。** 表示環境の差でたやすく割る。4.6〜4.8:1 の範囲で採る。
