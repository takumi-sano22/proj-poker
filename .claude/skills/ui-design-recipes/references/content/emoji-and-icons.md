# 絵文字とアイコン

> **いつ読むか**: 見出し・ボタン・空状態・ヒーロー表示に絵文字を置くとき／記号だけのボタンを作るとき／アイコンを追加するとき
> **前提**: `foundations/type-space-radius.md`（本文フォントの扱い）・`foundations/contrast-and-a11y.md`（アイコンだけの操作要素の扱い）
> サイズ・角丸・余白の値はそのまま再現してよい。絵文字そのものの選定は各プロジェクトの語彙で決める。

## 1. 要点

- 絵文字は「親しみを出したい面」だけに使う。業務系の一覧・テーブル・ナビには置かない（アイコン体系が無い面に 1 か所だけ入れると、そこだけ浮く。入口のタイルや見出しを並べるホームは例外・§2）。
- **1 つの概念に 1 つの絵文字**を対応表として持ち、使う場所はその対応表を指すコメントを残して照合できるようにする。**定義は 1 か所**（一覧に載る機能なら、その登録情報に 1 文字だけ持たせる）。
- **絵文字だけのラベルは禁止。** フォントが無い環境では四角（tofu）になり意味が消えるため、必ず語を添える。アイコンだけのボタンは `aria-label` を付け、絵文字自体は読み上げから隠す。
- サイズは装飾の強さに応じて 4 段程度に決め打ちし、フォントは本文の指定に任せる（絵文字専用の `font-family` を当てない）。
- 主役（アバター・キャラクター等）に関わる機能は、絵文字のままにせず主役の画像へ差し替える経路を持つと表現の統一感が出る。近くの別要素と記号が衝突するときは、絵文字をインライン SVG に置き換えてモチーフの形を微調整できるようにする。
- アイコンはライブラリを増やさず、インライン SVG（`viewBox="0 0 24 24"`・`w-5 h-5`）で描く。`stroke="currentColor"` か `fill="currentColor"` で親の文字色を継承させ、`aria-hidden="true"` を付ける。

## 2. 使う場所・使わない場所

| 使う | 使わない |
| --- | --- |
| 対話面の見出し・ボタンのラベル（語に添える） | 業務画面の一覧・テーブル・バッジ・ナビ |
| 空状態・ヒーロー表示（ログイン画面の主役アイコン等） | アイコン体系が定まっていない面に 1 か所だけ足す |
| バナーの見出し・準備中プレースホルダ | 状態を示すバッジ（状態は色と文言で示す。バッジは別 reference の対象） |

業務画面（管理系の一覧・テーブル）は、そもそもアイコン体系を持たない設計にできる。データがまだ無い空状態・絞り込みで 0 件の空状態のどちらも、アイコンを足さずに文言と枠だけで表す（`layout/admin-dashboard.md` §9）。未実装画面の「準備中」表示だけは、控えめな絵文字 1 つを段落中央に置いてよい（§4 の「準備中」サイズ・`layout/admin-dashboard.md` §10）。

**例外: 入口のタイルやセクションの見出しを並べるホーム。** 業務画面でも、各機能への入口をカード型のタイルで並べ、要約のセクションを見出しで区切るホームは、タイル・見出しごとに絵文字を 1 つ置いてよい。タイルでは絵文字だけだと「押せる」感が弱いので、丸い淡い面に載せて添える。その画面ではタイルも見出しも全部が絵文字を持つので、1 か所だけ浮くことにならない。同じ画面の空状態の文言に絵文字を添えるなら、その画面の対応表（見出し・タイルの絵文字）と同じ語彙から選ぶ（一覧・テーブルの画面の空状態には添えない）。

## 3. 1 つの概念に 1 つの絵文字（対応表と照合）

同じ機能が複数の一覧系 UI（機能サイドバー・機能一覧・使い方の説明・別画面のメニュー等）に重複して現れるプロダクトでは、絵文字の選定がその都度バラつくと「同じ機能なのに違う記号」という不整合が起きる。防ぐ手順は 2 段:

1. **対応表を 1 つ持つ**（概念名 → 絵文字 1 文字）。表は実装のどこか 1 箇所（機能の登録情報・定数ファイル等）に置き、UI 側はそこから読むだけにする。
2. **登録の外にある入口**（例: その機能一覧の対象ではない画面固有のメニュー項目）は絵文字を直書きせざるを得ないことがある。その場合も、コメントで「この概念は対応表のどれと同じか」を書いておく。実装が対応表側だけ変わって直書き側が取り残される、という事故を後から grep で見つけられるようにするため。

```tsx
// 一覧の登録情報に 1 文字だけ持たせる。UI 側では直書きしない。
type Entry = {
  id: string;
  icon?: string; // 絵文字 1 文字。一覧系 UI 全体で共有する
};

// 未定義なら既定の絵文字にフォールバックする
function EntryIcon({ icon }: { icon?: string }) {
  return <span aria-hidden="true">{icon ?? "🔧"}</span>;
}
```

- フォールバックの絵文字は 1 つに決め打ちする（アイコン欄が空のまま出荷されても、意味不明な空白ではなく「未設定」と分かる記号になる）。
- 対応表の外で同じ概念を指す絵文字を直書きした場合、対応表側を変えたら直書き側も一緒に直す。レビュー観点として「対応表に載っている概念を、対応表を経由せず別の絵文字で書いていないか」を横断で確認する。

## 4. 間隔とサイズ

| 用途 | 値 | Tailwind | なぜ |
| --- | --- | --- | --- |
| ヒーロー表示（ログイン等の主役アイコン） | 48px 相当 | `text-5xl` | 画面の主役として最初に目に入る大きさ |
| 準備中プレースホルダ | 30px 相当 | `text-3xl` | 本文より目立たせつつ、主役ほどの強さは持たせない |
| メニュー・カードのタイル | 44×44px の角丸枠に 24px 相当 | `h-11 w-11 rounded-xl text-2xl` | タップ領域 44px（`foundations/type-space-radius.md`）を満たしつつ中の絵文字を大きく見せる |
| 見出し脇の丸アイコン | 32×32px の円に 16px 相当 | `h-8 w-8 rounded-full text-base` | 見出しに添える控えめな標識。バッジ（件数）と並べても喧嘩しない大きさに抑える |
| 語と並べる絵文字 | 周囲の文字サイズを継承 | `flex items-center gap-2`（または半角スペース 1 つ） | 絵文字だけ拡大すると行の高さが乱れるため、文字サイズに乗せる |

- 絵文字は本文と同じフォントスタックの中で描く。専用の `font-family` を当てない（本文の日本語フォントに任せれば、その環境の絵文字フォントへ自動でフォールバックする）。
- タイル・丸アイコンのように「枠＋中央寄せ」で絵文字を置く場合は `flex items-center justify-center` を使う。語を伴わない記号なので、その枠自体に `aria-hidden` を付けるかどうかは §5 の判断に従う。

## 5. 絵文字だけのラベルは禁止

- **絵文字 1〜2 文字だけの視覚的ラベルを、唯一の説明にしない。** 絵文字が表示されない環境（フォント欠落・古いレンダラ）では四角の欠落記号になり、意味がまるごと消える。必ず短い語を添える（「⚙️」だけではなく「⚙️ 設定」のように、語のほうを主にして絵文字は先頭に軽く添えるだけにする）。
- **アイコンだけのボタン**（語を画面上に出さない設計）は `aria-label` に完全な説明を持たせ、内部の絵文字・アイコンは `<span aria-hidden="true">` または SVG の `aria-hidden="true"` で読み上げから隠す。読み上げ用の文言と画面上の絵文字を二重に読ませない。
- **文字列の中に埋め込んだ絵文字**（例: 見出しの先頭に置く「📗 ○○」）は `aria-hidden` を付けられない（テキストノードの一部のため）。この形は読み上げられる前提で、絵文字自体が意味を壊さない位置（先頭・語の前後）に置く。
- 語を添えれば足りる場面と、`aria-label` が要る場面を混同しない: 見出し・ボタンのテキストラベルは前者、記号だけのアイコンボタンは後者。

```tsx
// アイコンだけのボタン: 見える語が無いので aria-label が唯一の説明
<button type="button" aria-label="設定を開く">
  <span aria-hidden="true">⚙️</span>
</button>

// 語を伴うラベル: 絵文字は装飾として先頭に添えるだけ
<span className="flex items-center gap-2">
  <span aria-hidden="true">📌</span>
  <span>作業メモ</span>
</span>
```

## 6. 主役への置き換え・絵文字から SVG への置き換え

- **主役（アバター・キャラクター等）の振る舞いそのものを表す機能**は、一覧系 UI で絵文字の代わりに主役の画像を出す経路を持つと、そこだけ浮かずに済む。実装パターンは、絵文字と主役の画像のどちらを描くかを 1 個のブール値で切り替える共有部品にし、その値も§3 の登録情報に 1 か所だけ持たせる（絵文字自体はフォールバックとして残す）。切り替えの対象外にする面（例: 記号を並べて一覧性を優先したい機能一覧そのもの）を意図的に残す設計もあり得る。
- **絵文字が近くの別要素の記号と混同される**ことが実機で分かったら、絵文字をインライン SVG に置き換える。文字コードのグリフを変えられない絵文字と違い、パスの形を微調整して区別できるようにできる。置き換え後も `currentColor` で塗ることで、状態（有効・無効等）に応じた色の切り替えをテキスト色の仕組みにそのまま乗せられる。

```tsx
// 絵文字 ✨ の代わりに、モチーフを保ったまま形を調整できる SVG にする。
// 塗りは currentColor なので、有効・無効の色は親の文字色で切り替える
function SparkleIcon() {
  return (
    <svg viewBox="0 0 24 24" fill="currentColor" aria-hidden="true" className="h-5 w-5">
      <path d="M12 3Q14.1 9.9 21 12Q14.1 14.1 12 21Q9.9 14.1 3 12Q9.9 9.9 12 3Z" />
    </svg>
  );
}

// 使う側
<span className={enabled ? "text-brand-600" : "text-on-surface-disabled"}>
  <SparkleIcon />
</span>
```

## 7. アイコン（インライン SVG）

- ライブラリを依存に足さず、**インライン SVG** で描く。`viewBox="0 0 24 24"` を基準に、表示サイズは `w-5 h-5`（20px）を基準にする。
- 線画は `fill="none" stroke="currentColor" strokeWidth={2} strokeLinecap="round" strokeLinejoin="round"`、塗りのモチーフは `fill="currentColor"`。どちらも親要素の文字色をそのまま継承するので、hover・disabled の色替えはテキスト色の切り替えだけで済む。
- 装飾のアイコンには必ず `aria-hidden="true"` を付ける。語を伴わないアイコンだけのボタンは、ボタン側に `aria-label` を持たせる（§5 と同じ判断）。
- **同じ意味を持つ別のボタンと、形が一目でかぶらないようにする。** 記号のモチーフを決めるときは、近くにある別の操作の形（例: 四分割グリッドと棒グラフ、＋記号と星形）と比較し、シルエットで区別できるようにする。
- グラフ・チャートの類も同じ考え方で自前の SVG にする（詳細は `layout/admin-dashboard.md` §12）。

```tsx
function GearIcon() {
  return (
    <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth={2}
      strokeLinecap="round" strokeLinejoin="round" className="w-5 h-5" aria-hidden="true">
      <circle cx="12" cy="12" r="3" />
      {/* 歯車の歯（省略） */}
    </svg>
  );
}
```

## 8. 落とし穴

- **絵文字だけのタグ・ラベルを作る。** 表示されない環境で意味が消える（§5）。小さい面ほど「文字を削って絵文字だけにしたい」誘惑があるが、語を残す。
- **対応表を経由せず、同じ概念に別の絵文字を直書きする。** 見た目が近い一覧系 UI が複数あるプロダクトほど起きやすい。対応表を指すコメントを残し、変更時に横断確認する（§3）。
- **絵文字に個別の `font-family` を当てる。** 環境ごとの絵文字フォントへのフォールバックを妨げ、意図と違う見た目になりうる。
- **記号だけのボタンに `aria-label` を付け忘れる。** 見た目のアイコンが変わっても、スクリーンリーダー利用者には何のボタンか伝わらないまま残る。
- **業務系の一覧に思いつきで 1 か所だけ絵文字を足す。** アイコン体系が無い面では、その 1 か所だけが浮いて見える。

## 9. チェックリスト

- [ ] 絵文字は親しみを出す面だけに置き、業務系の一覧・テーブル・ナビには置いていない（入口のタイルや見出しを並べるホームは例外）
- [ ] 同じ概念には対応表の同じ絵文字を使い、直書きした箇所には対応表を指すコメントを残した
- [ ] 一覧に載る機能の絵文字は登録情報の 1 箇所だけで定義し、UI 側は直書きしていない。未定義時のフォールバックを決めた
- [ ] 絵文字だけのラベルを作っていない（必ず語を添えた）
- [ ] アイコンだけのボタンに `aria-label` を付け、内部の絵文字・SVG は `aria-hidden` にした
- [ ] サイズは装飾の強さに応じた段（ヒーロー・準備中・タイル・見出しの丸）から選び、絵文字専用のフォントは当てていない
- [ ] 主役に関わる機能・記号が衝突する絵文字は、画像や SVG への置き換えを検討した
- [ ] アイコンはライブラリを足さずインライン SVG（`w-5 h-5`・`currentColor`）で描いた
