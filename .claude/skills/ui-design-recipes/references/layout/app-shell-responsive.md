# アプリの骨組みと幅帯への対応

> **いつ読むか**: アプリ全体の外枠（ヘッダー・左右の列・本文）を組むとき／画面幅ごとに列の出し方を変えるとき
> **前提**: `foundations/surface-and-depth.md`（面のレシピ）・`foundations/type-space-radius.md`（角丸トークン）
> 形の値（幅・ブレークポイント・z-index）はそのまま再現してよい。

## 目次

## 1. 要点

- 外枠は `h-dvh flex-col` を頂点にし、**`html` 側の overflow を JS で止める**（`body` 側は使わない。理由は §2）。
- 幅・高さの縮小は `min-h-0` / `min-w-0` の連鎖で流す。**スクロールを持つ層は 1 つだけ**にし、二重スクロールを避ける。
- 幅帯は「ナビ列をドロワー化するか」「ツール列を常設するか」「中央にもう1列置けるか」の 3 段の判断で決まる。**帯を増やしすぎない**（本レシピは 5 帯＋高さ 1 条件）。
- 同じ機能への入口は、常設・折りたたみメニュー・ドロワーの **3 形態（variant）で中身を共有**し、外側の器だけを変える。
- 広い帯の中央寄せは `mx-auto` だけに頼らず、**幅を明示した対称の列**で挟む。閾値は検算式で求め、任意の値は JS の `matchMedia` で分岐する。
- z-index は **6 段に固定**する（10/20/30/40/50/60）。段を増やすと「どちらが上か」を都度確認する羽目になる。

## 2. 縦の骨組み（入れ物・overflow ロック・スクロールの層）

```
<html>                              overflow: hidden を JS で当てる（下記）
  <body class="min-h-dvh">
    <div class="flex h-dvh flex-col">   ← アプリ外枠。h-dvh は動的ビューポート高に追随する
      <header class="shrink-0">…</header>
      <div class="flex flex-1 overflow-hidden">   ← 横に並ぶ列の行。ここで一度だけ overflow-hidden
        <aside class="shrink-0 …">左ナビ列</aside>
        <main class="flex-1 min-w-0 flex flex-col overflow-hidden">
          <div class="flex-1 min-h-0 …">本文（ここだけが縦スクロールする）</div>
          <div class="shrink-0">下端に固定する入力欄など</div>
        </main>
        <aside class="shrink-0 …">右ツールレール</aside>
      </div>
    </div>
  </body>
</html>
```

- **`html` 側を止める理由**: 全面を覆うモーダルは閉じるときに `body.style.overflow` を空文字へリセットする実装が多い。アプリ外枠が `body` 側をロックしていると、モーダルを開閉するたびにロックが解けてしまう。`html` 側は CSS の overflow 伝播の仕様上、`body` の inline style と独立に効くため、モーダルの開閉に巻き込まれない。

  ```ts
  // マウント時に html を止め、アンマウント時に元の値へ戻す
  useEffect(() => {
    const html = document.documentElement;
    const prev = html.style.overflow;
    html.style.overflow = "hidden";
    return () => {
      html.style.overflow = prev;
    };
  }, []);
  ```

- **`min-h-0` / `min-w-0` の連鎖**: flex アイテムは既定で `min-height: auto` / `min-width: auto`（＝中身の最小サイズ）を持つため、`flex-1` を付けただけでは中身より縮まない。縦に潰したい経路には `min-h-0` を、横に潰したい経路（左右の固定幅列の合計がビューポートを超えても中央だけを縮めたい場合）には `min-w-0` を、**縮めたい先頭から縮めたい末尾まで途切れずに**付ける。1 か所でも抜けると、そこで縮小が止まって横（または縦）スクロールが漏れる。
- **スクロールする層は 1 つに絞る**。`main` 自身は `overflow-hidden` にし、実際にスクロールさせたい内側の 1 要素だけに `overflow-y-auto` を持たせる。両方に `overflow-y-auto` を付けると、外側と内側が同時にスクロールバーを持つ「二重スクロール」になり、どちらを操作しているか分からなくなる。
- 画面の地（背景グラデーション）を狭い幅で前倒しする話は色の役割なので `foundations/color-usage.md` を参照する（ここでは扱わない）。

## 3. 幅帯ごとの構成

列は 3 種類だけ考える: **左ナビ列**（一覧などの補助ナビ）・**本文列**（主コンテンツ・最大幅を持つ）・**右ツールレール**（機能への入口）。任意で本文の隣に**脇役のメモ列**（予約幅を持つ補助パネル）を置ける。

| 帯 | 幅 | 左ナビ列 | 右ツールレール | 本文列 | 主な入口 |
| --- | --- | --- | --- | --- | --- |
| 極狭 | 〜767px | 左ドロワー | 右ドロワー（ツール一覧の末尾に、ヘッダーから溢れた設定系の操作をまとめる） | 全幅 | ヘッダーの開閉ボタン 2 個（左右）＋画面端スワイプ |
| 狭 | 768〜1023px | ドロワー | ヘッダー右端の**折りたたみメニュー**（dropdown 形） | 全幅 | ヘッダーの折りたたみメニュー＋常設クラスタ |
| 中 | 1024〜1279px | 常設（幅 288px） | 折りたたみメニュー（dropdown 形） | 残り幅の中央・最大幅固定 | — |
| 広 | 1280〜1815px | 常設（288px） | 常設（展開 280px／折りたたみ 56px） | 中央・最大幅固定。メモは左ナビ列の下段 | — |
| 最広 | 1816px〜 | 常設（288px） | 常設（280px／56px） | 3 列構成（メモ＋本文＋対称スペーサー・§4） | — |
| 圧縮 | 高さ 820px 以下（任意の帯と併存） | — | — | ヘッダーの余白・主役表示を 1 段圧縮 | — |

- `Tailwind` の素の値: 768px=`md`・1024px=`lg`・1280px=`xl`。1816px と高さ 820px は Tailwind の既定ブレークポイントに無い**任意の閾値**なので §4 の JS 分岐で扱う。
- **左ナビ列と右ツールレールは別々の閾値を持つ**（左＝`lg`、右＝`xl`）。それぞれが独立に「常設で運用できる最小幅」を持つため、無理に 1 つの閾値へ揃えない。
- **同じ機能への入口は 3 形態（variant）で中身を共有する**: 常設パネル（rail）／ヘッダーに畳んだメニュー（dropdown）／モバイルのドロワー（drawer）。3 つとも「表示する項目の組み立て」は同じ関数から作り、変えるのは外側の器（幅・開閉の仕方・並び方）だけにする。中身のロジックを複製すると、片方だけ項目を直して表示がずれる。
- **ある列をドロワー化する閾値を動かすときは、その列に紐づく入口（開閉ボタン・折りたたみバー）を全部同じ閾値へ動かす。** 無関係な列の閾値まで動かさない。閾値を 1 つだけ変えて紐づく入口を動かし忘れると、その帯だけ「起動ボタンは消えたのに、対応する経路が無い」状態になる。
- 縦の圧縮（820px 以下）は `matchMedia("(max-height: 820px)")` で判定し、ヘッダーの余白や主役表示のサイズを 1 段小さいものへ切り替える。横の帯とは独立した軸（高さ）なので、どの横帯とも重ねてよい。

## 4. 中央寄せの作り方

広い帯で「本文列を中央に置いたまま、その隣に補助パネルを増やす」場合、`mx-auto` だけに頼ると事故る。

- **手段は「反対側にも同じ幅の列を置く」。** 補助パネル（幅 240px・列間 gap 24px）を本文列の左に置くなら、右にも同じ 240px+24px の**スペーサー列**（中身が空でも幅だけ持つ）を置く。ラッパ全体を「補助パネル＋本文列＋スペーサー列」の 3 列にし、ラッパ自体を `mx-auto` で親の中央へ置けば、対称な 3 列構成のおかげで本文列も自動的に親の中央に揃う。
- **`mx-auto` や `justify-center` だけで本文列を中央へ寄せようとしない。** 直下の flex アイテムに幅を明示しないと、`flex-basis: auto` の既定値が働いて「内容量に応じて縮む」動きをする。中間に幅を持たないラップ `div` を 1 つ挟むだけでも、必要幅がビューポートを超えた瞬間に本文列が最小幅まで潰れる（実測: 720px 想定の列が 484px まで縮む事故が起きる）。**幅を持つ列（本文列・補助パネル・スペーサー列）を flex の直下に並べ、中間ラップを挟まない。**
- **閾値は「必要な合計幅」から検算する。** 例（本文列 720px・補助パネル 240px・列間 24px・左ナビ 288px・右レール展開時 280px）:

  ```
  必要な中央エリア幅 = 本文列720 + (補助パネル240 + gap24) × 2   ← 対称に確保するので2倍
                       = 1248px
  必要な viewport    = 1248 + 左ナビ288 + 右レール280 = 1816px
  ```

  閾値ちょうどでは端数が出ることがあるが（中央エリアが奇数幅になる等）、両側の列が同じ端数を持つので中心のずれには影響しない。
- **右レールの展開／折りたたみは閾値の判定に含めない。** 判定に含めると、レールを畳んだ瞬間に補助パネルの置き場所（中央 or 左ナビ下段）が切り替わってしまい、視線の先で内容が飛ぶ。判定は「レールが最大幅のとき」で固定し、レールの開閉は本文列の中心位置（§5）だけに反映させる。
- **任意の閾値（Tailwind の既定ブレークポイントに無い値）は CSS のメディアクエリではなく JS の `matchMedia` で条件描画する。** CSS の `min-[1816px]:` のような任意値クラスと、JS 側の状態（左ナビ列の開閉等）を両方で判定すると、境界をまたいだ瞬間に「CSS 上は広い帯なのに JS 上はまだ狭い帯用の state」という不一致が起きやすい。1 か所（JS の `matchMedia`）に判定を集約し、**同じ内容を 2 箇所に同時マウントしない**（狭い帯用の描画と広い帯用の描画を両方 DOM に置いて CSS で出し分けると、スクリーンリーダーが同じ内容を二重に読み上げる）。

  ```ts
  const [wide, setWide] = useState(false);
  useEffect(() => {
    const mql = window.matchMedia("(min-width: 1816px)");
    const update = () => setWide(mql.matches);
    update();
    mql.addEventListener("change", update);
    return () => mql.removeEventListener("change", update);
  }, []);
  ```

## 5. 開閉で位置が動く／動かない

- **予約列（補助パネルなど）は開閉に関わらず幅を固定する。** 中身が 0 件・折りたたみのどちらでも列の幅は変えない（畳むのは高さだけ）。幅まで可変にすると、開閉のたびに列の外にある開閉トグル自体の x 座標が動いてしまう。**幅は固定・高さだけ畳む**、を分けて考える。
- **左ナビ列・右ツールレールの開閉（ドロワーの開閉・レールの展開/折りたたみ）は、本文列の中心を親（中央エリア）の中心へ追従させてよい。** ヘッダーや帯状の装飾も親の全幅を使う以上、それらの中心と本文列の中心を揃えるほうが「動かない」よりも視覚的に自然になる。レールを畳んで空いた分だけ中央エリアが広がり、本文列の中心もその分だけ動く——これは意図した挙動であって、固定すべき「位置」ではない。
- 「動かさない」対象と「動いてよい」対象を混同しない: **予約列自身の幅とトグル位置は固定**、**列を含むエリア全体の中心追従は許容**。

## 6. z-index の段

新しい値を作らず、次の 6 段のどれかに当てはめる。

| 段 | 役割 | 例 |
| --- | --- | --- |
| 10 | ホバー／フォーカスで一時的に出る短い説明 | ボタンの説明ラベル、レール項目のツールチップ |
| 20 | 軽い浮遊ボタン・パネルからはみ出す補助の面 | 「最新へ戻る」ボタン、脇役のメモ面から上へ広げるオーバーレイ |
| 30 | トリガーに付くポップオーバー・全画面演出の上に浮く操作クラスタ | 設定値を選ぶメニュー、全画面表示の上に浮かせる操作ボタン列 |
| 40 | 通常 UI より上・ドロワー/モーダル未満の一時通知・帯 | 画面端のジェスチャ受け取り帯、画面下端の一時トースト |
| 50 | 最前面の対話（ドロワー・モーダル） | ドロワー、モーダル |
| 60 | モーダルの上にさらに重ねるモーダル | 確認ダイアログを別モーダルの上に出す場合 |

- 段は「何の上に来る必要があるか」で選ぶ。同じ段の中では DOM の後勝ちになるため、**無関係な要素が同じ段（例: 10）を持つと、後から描画された方が意図せず前面に来る**ことがある。
- **6 段以外の値を作ってよいのは、衝突を解くときだけ。** 間の値（例: 15）を割り当てて両方の関係を崩さずに解く（テーブルの sticky な見出し等・`layout/admin-dashboard.md` §7）。
  ヘッダーに畳んだメニューのように、**ヘッダー自体の重なりより確実に前へ出したい**ものを 50 に置く例もある。どの段にしたかと理由を、その要素のコメントに残す。

## 7. 未対応の点

- **safe-area（ノッチ・ホームバー）**: 外枠には `env(safe-area-inset-<side>)` を反映していない（画面端に張り付くシートには入れてある: `components/drawer-and-sheet.md` §3）。ノッチ付き端末で外枠の端の要素が隠れる余地がある。外枠に入れるなら `viewport-fit=cover` の指定とセットで行う。**未実装の推奨**。
- **ソフトキーボード表示時の高さ**: `h-dvh` は URL バーの表示/非表示には追随するが、ソフトキーボード表示時の可視領域変化を個別に調整していない。入力欄の可視性が必要な画面では、キーボード表示を検知して調整する仕組みを別途足すことを推奨する。**未実装の推奨**。

## 8. 落とし穴

- **`body` 側の overflow ロックはモーダルに上書きされる。** 全面モーダルが閉じるときに `body.style.overflow` をリセットする実装は多く、外枠と衝突する。ロックは `html` 側に置く（§2）。
- **中間ラップ `div` を挟むと幅固定が壊れる。** 幅を持たない flex アイテムは `flex-basis: auto` で内容依存に縮む。中央寄せの列構成（§4）・列の直下要素には必ず幅を明示する。
- **スクロール領域を 2 段（外側 `overflow-hidden`＋内側 `overflow-y-auto`）にせず、うっかり両方に `overflow-y-auto` を付ける。** 二重スクロールになり、どちらの層をスクロールしているか分からなくなる。
- **`min-w-0` / `min-h-0` を経路の途中で 1 か所抜かす。** 固定幅列の合計がビューポートを超えたときに、抜けた箇所より先が縮まらず、想定より手前で横（または縦）スクロールが漏れる。
- **任意の閾値を CSS の任意値クラスと JS の両方で別々に判定する。** 境界をまたいだ瞬間に CSS 側と JS 側の認識がずれる。1 か所（JS の `matchMedia`）に集約する。

## 9. チェックリスト

- [ ] overflow のロックは `html` 側（JS）に置いた（`body` 側に依存していない）
- [ ] スクロールする層は 1 つだけで、外側は `overflow-hidden` にした
- [ ] 固定幅列の合計がビューポートを超えても中央だけが縮むよう、経路の全部に `min-w-0` / `min-h-0` を通した
- [ ] 中央寄せは幅を明示した対称の列で作り、`mx-auto` だけに頼っていない
- [ ] 任意の閾値は JS の `matchMedia` に集約し、同じ内容を 2 箇所に同時マウントしていない
- [ ] 予約列の幅は開閉に関わらず固定し、トグルの位置が動かない
- [ ] z-index は 6 段のどれかに当てはめた（間の値は衝突を解くときだけ・理由をコメントに残した）
- [ ] safe-area・ソフトキーボード対応は未実装であることを認識している
