# トリガーに付いて出る選択メニュー（ポップオーバー / ドロップダウン）

> **いつ読むか**: ボタン 1 個に選択肢を畳んだメニュー（設定値を選ぶメニュー・ドロップダウン等）を作るとき
> **前提**: `foundations/surface-and-depth.md` §2・§5（「トリガーに付いて出る浮き面」は `raise`・L4 にしない）、`foundations/motion.md` §4（入場演出）
> 形の値・所要時間はそのまま再現してよい。色は役割名で書いてある。

## 1. 要点

- 面は「**トリガーに付いて出る浮き面**」（`foundations/surface-and-depth.md` §5 の注記）。別レイヤー（L4・`overlay`・20px）にはしない。
  白単色＋淡い縁＋`raise`＋角丸 12px に留める。画面から切り離すほどの距離ではないため。
- **尻尾（コネクタ）** で本体との連続性を示す。45° 回した正方形に 2 辺だけ枠を付ける。
- 入場は `@starting-style`（`foundations/motion.md` §4）、閉じるときは unmount で即時に消える。
- **閉じる経路は 3 種**（選択・Esc／外側クリック／Tab での離脱）で、フォーカスの動かし方が違う。
  「押した結果メニューが消える」経路だけがフォーカスを戻す。
- トリガーの見えているラベルが短い（アイコンのみ・単語 1 つ）ときは、`aria-label` にその語と
  現在値の両方を文字で含める。
- 開いた**瞬間だけ**現在値へフォーカスする。開いている間の値の変化ではフォーカスを奪わない。

## 2. 位置とサイズ

トリガーの真上に開き、右端をトリガーの右端に揃える。

```
absolute bottom-full right-0 mb-2
```

| 項目 | 値 | なぜ |
| --- | --- | --- |
| 基本幅 | `w-56`（14rem / 224px） | 選択肢のラベル＋説明が 1〜2 行で収まる幅 |
| 上限幅 | `max-w-[calc(100vw-7rem)]` | 画面端で切れないための上限。`7rem`（112px）はトリガーの画面上の位置＋隣接する固定要素の幅から逆算した値 |
| 縦の隙間 | `mb-2`（8px） | トリガーとの間隔 |
| 内側の余白 | `p-1`（4px） | 選択肢のクラスと合わせて 44px 前後のタップ領域を保つ |

- **上限幅の計算は呼び出し側のレイアウトに依存する外部値。** トリガーの位置や隣に並ぶ要素の数・幅を
  変えたら、この上限も見直す（メニュー側のコンポーネントからは検知できないため、変更時に手で合わせる）。
  最小サポート幅（320px 程度）でも左右に数 px 残ることを実機かブラウザ幅リサイズで確認する。
- 右揃え・上向きに開くのは、トリガーが画面下端付近（入力欄の周辺等）にあるときの既定。
  画面上端付近のトリガーなら `top-full mt-2` に、左に寄せたいなら `left-0` に読み替える。

## 3. 面

```
rounded-panel border border-<淡い縁> bg-surface-raised p-1 shadow-raise
```

| 役割 | 値 | なぜ |
| --- | --- | --- |
| 背景 | `surface-raised`（白単色） | 淡いグラデにすると、読む対象の面（吹き出し等）と区別が付かなくなる |
| 縁 | `brand-200` の 60%（`border-brand-200/60`）など、中身の選択中項目と同系色相の淡い縁 | 縁だけで独立した面であることを示す。操作の境界ではない（項目自体が操作要素）ので装飾の縁でよい |
| 角丸 | `rounded-panel`（12px） | 操作要素（10px）より大きく、別レイヤー（20px）より小さい。小さな浮き面であることを角で示す |
| 影 | `shadow-raise` | トリガーから浮いた面。`shadow-overlay` は使わない（重すぎる） |
| 内側余白 | `p-1`（4px） | 選択肢のクラスとの間に枠のゆとりを作る |

- 選択肢（項目）は `flex w-full items-center gap-2 rounded-control px-3 py-2 text-left` の独立した操作要素にし、
  既定は `text-on-surface hover:bg-surface-brand`、選択中は濃い塗り
  （`bg-brand-gradient text-on-brand shadow-rest inset-shadow-edge-brand`）にする。濃い塗り＋内側ハイライトが
  「押せる・選ばれている」の標識になる（`foundations/surface-and-depth.md` §4 の軸）。無効な項目は `disabled:opacity-50`。
- 項目の説明文（サブラベル）は選択中でも不透明度を下げない。白文字は塗りの端で 4.5:1 を割らない
  段から使っているため、薄めると AA を割る（`foundations/contrast-and-a11y.md` §4）。

## 4. 尻尾（コネクタ）

```
absolute -bottom-1.5 right-9 h-3 w-3 rotate-45 rounded-[2px] border-b border-r border-<面と同じ縁色> bg-surface-raised
```

- **12px の正方形**（`h-3 w-3`）を 45° 回し、**下辺と右辺だけ**に本体と同じ縁色の枠を付ける。
  回すと上向きの菱形になり、下辺・右辺の枠が本体の上端の枠と視覚的につながる。
- 角は `rounded-[2px]` で少しだけ丸める。完全な直角だと本体の角丸から浮いて見える。
- **位置合わせ**: メニューがトリガーの右端に揃っている（`right-0`）前提で、尻尾の中心をトリガーの
  中心へ合わせる。`right` の値 ≒ トリガー幅の半分 − 尻尾の半分（6px）。例えばトリガー幅が
  80px なら 40 − 6 ＝ 34px になり、既存の段で最も近い `right-9`（36px）を使う
  （2px のずれは目で見て分からない範囲。ぴったり合わせたいなら `right-[34px]`）。
- **`-bottom-1.5`**（-6px）で本体の下端から半分だけはみ出させ、トリガー側を指す形にする。
  上向きに開く場合は下端に、下向きに開く場合は上端（`-top-1.5`）に置き換える。
- 塗りは本体と同じ `bg-surface-raised`。塗りが違うと継ぎ目が透けて見える。

## 5. 入場演出

`foundations/motion.md` §4 の `@starting-style` パターンをそのまま使う。専用のグローバルクラスを
1 つ用意し、`transform-origin` をトリガー側（尻尾のある角）に合わせる。

```css
.popover-menu {
  transform-origin: bottom right; /* 右下から出てくる場合。開く向きに合わせて変える */
}
```

- 条件レンダーで unmount する実装なら、**閉じるときの演出は不要**（即座に消える。`foundations/motion.md`
  §4 の注記どおり情報は失われない）。
- `transition-property: opacity, transform` の短縮形にしない理由・reduced-motion での扱いは
  `foundations/motion.md` を参照（ここでは再掲しない）。

## 6. 閉じ方とフォーカスの後始末

| きっかけ | 閉じるか | フォーカス |
| --- | --- | --- |
| 項目を選択 | 閉じる | 呼び出し元が指定した戻り先（例: 入力欄）へ**戻す** |
| `Esc` | 閉じる | 同上へ**戻す** |
| 外側の pointerdown | 閉じる | **動かさない**（ユーザーが押した先にそのまま乗る） |
| メニュー外への `blur`（Tab で外へ抜けた等） | 閉じる | **動かさない**（自分で移した先を尊重する） |
| トリガー自体が操作不能になった（無効化など） | 閉じる | メニュー内にフォーカスがあった場合だけ戻り先へ**戻す** |

- **「選ぶ／`Esc`」と「外側クリック／`Tab`」でフォーカスの扱いを分ける。** 前者は「メニューが消えた
  ことでフォーカスの持ち主が消える」経路なので、同じイベントの中で戻り先へ移す。後者は
  ユーザーが自分で別の場所を選んだ結果なので、奪わない。
- **外側クリックの検知はメニュー要素の `ownerDocument` に `pointerdown` を capture 登録する。**
  素の `document` に張ると、別ウィンドウ相当のポータル（要素自身が別の `Document` を持つ
  切り出しウィンドウ）で開いたメニューの外側クリックを拾えない。capture にするのは、途中で
  `stopPropagation` されても取りこぼさないため。
- **操作できなくなったら自動で閉じる。** トリガーやメニューが disabled になるタイミングで
  開いたままにしない。閉じる前に「メニュー内にフォーカスがあったか」を判定してから戻す
  （無ければ何もしない＝ユーザーが既に他へ移っている）。

## 7. aria

| 対象 | 属性 | なぜ |
| --- | --- | --- |
| トリガー | `aria-haspopup="menu"` | メニューを開くボタンであることを伝える |
| トリガー | `aria-expanded={open}` | 開閉状態 |
| トリガー | `aria-controls={open ? menuId : undefined}` | **開いている間だけ**メニューの id を指す。条件レンダーでメニュー自体が閉時に DOM から無いなら、存在しない id を指させない |
| トリガー | `aria-label` に見えている語＋現在値を含める | トリガーの見た目の文字が短い（アイコンのみ・単語 1 つ）と、読み上げ名がその語を含まない場合がある。音声操作は画面に見えている語で対象を探すため、見えている語を `aria-label` から欠かすと「その名前で押せない」状態になる（WCAG 2.5.3 Label in Name） |
| メニュー本体 | `role="menu"` ＋ `aria-label` | メニューの目的を短く説明する |
| 各項目 | `role="menuitemradio"` ＋ `aria-checked` | 単一選択の選択肢群であることを伝える（複数選択なら `menuitemcheckbox`） |

## 8. キーボード

- **閉じたトリガー上で `↑` `↓` を押すと開く。** ネイティブな `Enter` / `Space` に加えた入口
  （メニューボタンの通例）。開いている間の `↑` `↓` は項目移動として扱う。
- **開いた瞬間だけ**、現在選ばれている項目へフォーカスする。「開いている／閉じている」の状態変化
  ではなく、「閉→開の切り替わりが起きたその 1 回」を検知する（直前の開閉状態を保持して比較する）。
  こうしないと、開いたまま値だけが外部要因で変わったときにもフォーカスを奪ってしまう。
  現在値が選べない状態（無効化されている）なら、選べる項目のうち先頭へ寄せる。
- **`↑` `↓` は無効な項目を飛ばして巡回する。** 選べる項目だけの並びを作り、末尾から先頭・
  先頭から末尾へ折り返す。
- **現在位置は押されたその瞬間に `activeElement` から読む。** state に「今どこにいるか」を
  持たない。Tab やクリックでも項目へフォーカスが移りうるので、覚えておく方式だとその経路を
  経由したときに古い値のまま動いてしまう。
- `Esc` は選択を確定させずに閉じ、戻り先へフォーカスを返す。

## 9. 落とし穴

- **上限幅の `calc(100vw - N)` を決め打ちのまま放置する。** 隣接する要素の数や幅が変わると
  画面端で切れる。呼び出し側のレイアウト変更時に必ず見直す。
- **`aria-controls` を常に同じ id で出す。** 条件レンダーで閉時に要素自体が存在しないなら、
  存在しない id を指させたままにしない（開いている間だけ出す）。
- **尻尾の塗り・縁色を本体と揃え忘れる。** 継ぎ目が透けて、浮いた別パーツに見える。
- **外側クリックの listener を素の `document` に張る。** 別ウィンドウ相当のポータルで
  開いたときに外側クリックを拾えなくなる。
- **開いている間の値の変化のたびにフォーカスを奪う。** 「開いた瞬間」だけに絞らないと、
  外部要因での値変化がユーザーの操作中のフォーカスを奪う事故になる。
