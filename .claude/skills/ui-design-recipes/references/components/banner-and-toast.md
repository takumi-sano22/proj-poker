# バナーとトースト

> **いつ読むか**: 一時的な知らせ（トースト）／画面上部や入力欄の上に出るお知らせ・初回ヒント・
> 操作を求める提案（バナー）を作るとき
> **前提**: `foundations/surface-and-depth.md`（面のレシピ・選択待ちの例外）、
> `foundations/contrast-and-a11y.md` §8〜9（hover 能力・キーボード割り当て条件）
> 形の値・時間はそのまま再現してよい。色は役割名で書いてある。

## 1. 要点

- **トーストは浮かせて重ねる（`fixed`）。バナーは通常フローに乗せる。** バナーを `fixed` /
  `absolute` にしないのは、背景を透かす面（背後に常時描画される演出等）の pointer-events /
  z-index の罠をそもそも踏まないため。
- トーストは `role="status"` ＋ `aria-live="polite"` を必ず持つ。「押しても無反応に見える」を
  解消するための知らせなので、画面を見ていない利用者にも操作への応答として届く必要がある。
- 自動で消える時間は**内容の重さ**で決める。やり直しが効く軽い知らせは短く、見逃すと
  やり直せない失敗の知らせは長くする。
- **主要アクションへの自動フォーカスは、競合が無ければ即時、競合しうるなら次フレームへ遅らせる。**
- 選択を求める帯（提案・確認）は、面のレシピの中で唯一「読むだけでなく選ぶ」役割を持つため、
  会話や通常の帯とは別の色相を割り当てる（`foundations/surface-and-depth.md` §5 の例外）。

## 2. トースト

```
fixed bottom-4 left-1/2 z-40 -translate-x-1/2
flex w-[calc(100%-2rem)] max-w-sm items-start gap-2
rounded-card border px-4 py-3 shadow-overlay
```

| 項目 | 値 | なぜ |
| --- | --- | --- |
| 位置 | `fixed bottom-4 left-1/2 -translate-x-1/2` | 画面下中央固定。`left-1/2` ＋ 自身の半分だけ戻す変換で、幅が変わっても中央が保たれる |
| 幅 | `w-[calc(100%-2rem)]`（左右 16px ずつ確保）＋ `max-w-sm`（384px）〜`max-w-xs`（320px） | 文言が短ければ `xs`、説明を含むなら `sm`。狭い画面では画面幅いっぱいに広がらず両端の余白が残る |
| 重なり順 | `z-40` | 通常の画面要素より前面。モーダル（別レイヤーの `overlay`）よりは背面に置く運用にする |
| 面 | `rounded-card border border-border bg-surface-raised shadow-overlay`（不透明な面）／`border-brand-200/60 bg-surface-raised/60 backdrop-blur-md`（背景を透かす面） | 呼び出し元が不透明な面か透かす面かで出し分ける。透かす面では背景を半透明＋ぼかしにし、縁は淡い光の縁にする |
| 本文 | `flex-1 text-sm leading-relaxed text-on-surface` | 折り返し前提。閉じるボタンとの間に `gap-2` |
| 閉じるボタン | `shrink-0` の `×`。`text-on-surface-subtle hover:text-on-surface` ＋ `aria-label="閉じる"` | 見た目の `×` だけでは読み上げ名が無いので `aria-label` を必須にする。**余白なしの `×` は押せる範囲がアイコンボタンの下限 40px に届かない**ので、`min-h-10 min-w-10` を足す（`foundations/type-space-radius.md` §5） |

| 用途 | 自動で消えるまで |
| --- | --- |
| 一時保存・非対応環境の案内など、やり直しが効く軽い知らせ | 6000ms |
| 操作の失敗など、見逃すとやり直せない知らせ | 8000ms |

- `role="status"` ＋ `aria-live="polite"` を必ず付ける。
- **自動消去のタイマーは、トーストの作り方で張り方を分ける。**
  - **表示のたびにマウントする型**（出すときに描画し、閉じたら消す）: 最新の「閉じる」関数は ref に保持し、タイマーはマウント時に一度だけ張る。
    effect の依存に親から渡された関数を直接入れると、親が再描画のたびに新しい関数を渡す作りでは、更新が続く間タイマーが張り直され続けて永久に消えない。
  - **常時マウントして中身を差し替える型**: 文言そのものではなく**発生回数（連番）**をタイマーの依存に含める。文言だけを見ていると、同じ失敗が続けて起きても
    値が変わらず effect が再実行されず、最初の知らせのタイマーが 2 回目の知らせを直後に消してしまう。この型で「閉じる」関数を依存に入れるなら、親側で `useCallback` 等により参照を安定させる。
- 閉じるボタンに開いた瞬間フォーカスを当てる場合（Enter でも閉じられるようにしたいとき）は、
  他に競合するフォーカス処理が無ければ `useEffect` から直接 `focus()` してよい。

## 3. バナー

画面上部や入力欄の上に、通常のレイアウトの一部として挿入する帯。丸めない・浮かせない。

```
flex shrink-0 flex-col gap-2 border-b px-4 py-2.5 sm:flex-row sm:items-center
```

| 項目 | 値 | なぜ |
| --- | --- | --- |
| レイアウト | `flex-col`（狭い画面）→ `sm:flex-row sm:items-center` | 本文とアクションを、狭い画面では縦に、余裕があれば横に並べる |
| 縁 | `border-b`（上下の面を仕切るだけ） | 通常フローの帯なので角丸・影は持たない |
| 面（常設のお知らせ） | `surface-brand` ＋ `border-brand-200` | 常設の告知は既定のブランド色でよい |
| 面（一度きりの初回ヒントなど、目立たせたい帯） | **会話面と色相の離れた淡い面**。専用色相が無ければ、状態色の最も淡い段を**面だけ**借りる（例: `warning-50` ＋ `border-warning-500/40`、文字は `on-surface` のまま） | 会話面がブランド色で占められている画面では、同系色の帯は地に沈んで読まれない。状態色を借りるのは妥協なので、文字色まで状態色にしない・本物の注意表示と並ぶ場所では使わない（次行）という条件を守る（`foundations/color-usage.md` §2） |
| 面（背景を透かす文脈・注意表示と並ぶ場所） | `border-brand-200/60 bg-surface-raised/60 backdrop-blur-md` | 借りた状態色の帯が本物の注意の帯と隣り合うと、1 枚の警告帯に誤読される。そういう場所では中立のガラス面に切り替えて色を分離する |
| テキスト側の伸縮 | 本文側に `flex-1` を持たせない。`min-w-0` で縮む側だけ許可する | 伸ばすとアクションボタンが帯の反対端まで離れ、「読んだ流れで押す」動線が切れる |

**自動フォーカス（次フレームへ遅らせる理由）**: 選択を求める帯など、表示と同時に主要アクションへ
フォーカスを当てたい場合は `requestAnimationFrame` で 1 フレーム遅らせる。

```ts
useEffect(() => {
  const id = requestAnimationFrame(() => {
    primaryActionRef.current?.focus();
  });
  return () => cancelAnimationFrame(id);
}, [/* 表示内容が切り替わるたびに当て直す依存 */]);
```

同じ画面に「入力欄が使えるようになったら自動でフォーカスする」のような**別のフォーカス処理**が
存在すると、同じフレームで両方が `focus()` を呼び合ってどちらが勝つか不定になる。1 フレーム
遅らせることで、先に走る側のフォーカス処理と競合しない。**競合する他のフォーカス処理が無ければ
遅らせる必要は無い**（トーストの閉じるボタンのように即時 `focus()` でよい場面もある）。

**キーヒントの出し分け**: 帯の中にキーボード操作の入口がある場合、ヒント（`kbd` 要素）は
`foundations/contrast-and-a11y.md` §8 の hover 能力による出し分け（`hover-fine` 系）でのみ表示する。
タッチ環境ではキー操作自体ができないため、効かないヒントを見せない。ヒントに書くキーは
**実装を読んで実際に効くものだけ**にする（同 §9）。

## 4. 選択待ちの面（面のレシピの例外）

「読むだけでなく選ぶ」帯（提案・確認）は、通常の帯や会話の面と同じ色相を使わない
（値は `foundations/surface-and-depth.md` §5 の例外行が一次情報）。会話の色相のまま塗ると、
選択待ちの帯が会話の一部に見えて、操作を求めていることが伝わらない。

- **色相を会話の主色から意図的にずらす**（隣接色相のアクセント）。角丸は「操作を求めている面」
  として操作要素と同じ段を使い、影は会話面から浮かせる 1 段を付ける。
- 選択肢が横並び 2 択なら、`role="group"` ＋ `aria-describedby` でキーヒントをグループの説明に
  紐づけ、矢印キーで選択肢同士のフォーカスを移動できるようにする。
  **`aria-describedby` が直接指す要素は、`display: none` でも説明として読み上げられる。** ヒントを hover-fine のときだけ見せていても、
  タッチ環境で効かないキーの説明が読まれうる。避けたいなら、hover-fine を `matchMedia` で判定して `aria-describedby` 自体を付け外しする。
- 表示時は既定の選択肢（多くは肯定側）へ自動フォーカスする（前節の rAF 遅延を使う）。
- 幅が狭い文脈（小さな補助ウィンドウ等）でも使う共有部品にする場合は、アクションの並びに
  `flex-wrap` を許可し、狭いときだけ折り返す（広い文脈での見た目は変えない）。

## 5. 落とし穴

- **バナーを `fixed` / `absolute` にする。** 背景を透かす面（背後に常時描画される演出等）の
  pointer-events / z-index の罠を自分で作ってしまう。通常フローに乗せれば踏まずに済む。
- **トーストの自動消去タイマーを文言の変化だけで再判定する。** 同じ文言の失敗が連続すると、
  2 回目以降が正しい時間表示されない。
- **表示ごとにマウントする型で、閉じる関数をタイマー effect の依存に直接入れる。** 親の再描画で永久にタイマーが張り直され、
  自動的に消えなくなる。
- **状態色（warning 等）を装飾に流用しながら、文字色まで状態色に寄せる。** 「淡い面だけ借りて
  文字は通常色のまま」にしないと、警告の意味だと誤読される。
- **選択を求める帯を会話と同じ色相のまま塗る。** 選ぶべき帯だと気づかれない。
- **効かないキーのヒントを表示する。** 実装を確認せずに書くと、押しても反応しないヒントを
  見せてしまう。

## 6. チェックリスト

- [ ] トーストは `fixed` ＋ `role="status"` ＋ `aria-live="polite"`、バナーは通常フローに乗せている
- [ ] 自動で消える時間を知らせの重さ（やり直せるか）で決めた
- [ ] 連続する同種の知らせでタイマーが正しく張り直る（発生回数を依存に含めた）
- [ ] タイマーの張り方をトーストの型（表示ごとにマウント／常時マウント）に合わせた
- [ ] トーストの閉じるボタンは押せる範囲が 40px 以上
- [ ] 自動フォーカスは競合の有無に応じて即時 / 次フレーム遅延を使い分けた
- [ ] キーヒントは hover-fine のときだけ、実装で確認した効くキーだけを表示している
- [ ] 選択を求める帯は会話と別の色相・面のレシピの例外を使っている
