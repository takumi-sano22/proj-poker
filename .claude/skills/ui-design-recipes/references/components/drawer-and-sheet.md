# ドロワー・半透明のシート・端スワイプ

> **いつ読むか**: 画面端から出る一覧・ナビゲーションを作るとき／スワイプで開閉する導線を足すとき
> **前提**: `components/modal.md`（Esc・Tab トラップ・スクロールロックの基本形はこちらと同じ考え方）、`foundations/motion.md`（reduced-motion の止め方）
> 形の値（幅・z-index・しきい値）はそのまま再現してよい。色は役割名で書いてある。

## 目次

1. 要点
2. ドロワー（条件描画型）
3. 半透明のシート（常時マウント型）
4. 画面端スワイプの帯
5. 落とし穴
6. チェックリスト

## 1. 要点

- 画面端から出す面には **2 通りの実装型**がある。「開いているときだけ DOM に存在する」条件描画型と、「常に DOM にあり `transform` で出し入れする」常時マウント型。**追従アニメーションが要るかどうか**が分かれ目——条件描画型はマウント/アンマウントの瞬間に切り替わるだけなので動きを付けられない。
- 条件描画型は「閉じている」= DOM に無いので、`inert` や `aria-hidden` を自分で管理する必要が無い。常時マウント型は閉じていても要素が残るため、**`inert` と `aria-hidden` を明示しないと閉じている間もタブ順・支援技術から触れてしまう**。
- 閉じるボタンは、パネルが張り付く画面の物理的な端とは**反対側**に置く。端に置くと指が届きにくく、OS 標準のエッジジェスチャとも競合しやすい。
- Tab トラップ・スクロールロック・フォーカス復帰は `components/modal.md` §3 と同じ考え方で持つ。ただし**どこで持つか（面自身か、画面側で 1 か所か）は画面の構成で決まる**（§2・§3）。新しい面を足すときは、既存の面がどちらの前提に乗っているかを先に確かめる。
- 画面端からの水平スワイプで開閉する帯を敷く場合、**縦スクロールは奪わない**（`touch-action: pan-y`）。しきい値は「対応する開閉ボタンが出る幅」と一致させ、ジェスチャと見た目の導線を食い違わせない。

## 2. ドロワー（条件描画型）

開いている間だけ `open && <Drawer />` のように条件描画する。

```
fixed inset-0 z-50 flex            … 外枠
absolute inset-0 <scrim>           … 覆い（クリックで閉じる）
w-72 max-w-[80vw]                  … パネル幅 288px（狭い画面では画面幅の 80% で頭打ち）
```

左に出すパネルは詰めたまま、右に出すパネルは `ml-auto` で右端へ寄せる。

### 覆い・パネル

- 覆いは半透明の中立色（`foundations/color-usage.md` の `scrim`）。パネルは `bg-surface-raised` の単色＋`shadow-overlay`。
- パネルの `onClick` は `stopPropagation()` して、覆いの `onClick` にだけ閉じる処理を割り当てる（`components/modal.md` §3.2 と同じ形）。

### フォーカスの記憶と復帰

- 開いた瞬間の `activeElement` を覚えておき、閉じたらそこへ戻す。
- **画面端スワイプで開いた場合、開いた瞬間の `activeElement` はほぼ確実に `body`。** `body` へ `focus()` しても何も起きないため、「覚えていた要素が無い（`body` のまま）」ときは決め打ちの復帰先（例: 主要な入力欄）へ明示的にフォーカスを戻す。
- 記憶した要素が実は別の実行文脈（例: 別ウィンドウとして切り出した面）の要素だと、`instanceof` によるフォーカス可能判定が常に偽になることがある。**「`focus` 関数を持つか」で判定する**ほうが、文脈をまたいでも壊れない。

### Tab トラップ

`components/modal.md` は document に張るが、**この型は要素自身に張ってもよい**（開閉のたびに毎回 mount し直すので、要素自身に張ったリスナーも一緒に張り直される。条件描画である以上、フォーカス中の要素が消えて `body` へ抜ける心配自体が起きにくい）。ただし document に張る方式のほうが「予期しない再描画でフォーカスが外へ落ちる」ケースにも耐えるため、**より安全なのは document 側**。どちらを選ぶかは、パネルの中身が動的に組み替わるか（アコーディオン・タブ切替がある）で判断する。

### 背後のスクロール停止

この型自体はスクロールロックを持たないことがある。**理由**: 呼び出し元の画面が最初から「常にビューポート全体を固定し、背景そのものがスクロールしない」構成（例: チャットのように 1 画面で完結する UI）なら、ドロワーの開閉状態にかかわらず背景は元々動かない。この場合、ロックの責務は個々のドロワーではなく画面側（1 か所）が持つ。**画面側がその前提を崩す（部分的にスクロールする領域を持つ）場合は、ドロワー自身がロックを持つ必要がある**——`components/modal.md` §3.6 の参照カウント式を使う。

### 閉じた状態の inert / aria-hidden

条件描画型は開いていないとき DOM に存在しないため、`inert` / `aria-hidden` を持たせる必要が無い（存在しないことそのものが遮断になる）。**常時マウント型（§3）へ作り替えて動きを付けるときは、この安全さが失われる**ので、そちらで明示する。

### 閉じるボタンの位置・タップ領域

- パネルが画面の左端に張り付くなら、閉じるボタンは右側（内側）に置く。右端に張り付くなら、見た目の並びだけ反転させて左側（内側）に閉じるボタンを出す（DOM 順は変えなくてよい。フォーカス可能な要素がボタン 1 個だけなら Tab 順に影響しない）。
- 閉じるボタンの押せる範囲は、アイコンだけのボタンの下限 40px（`foundations/type-space-radius.md` §5）を守る。画面の端に張り付く面では指が端に寄りやすいので、`min-h-[44px] min-w-[44px]` まで広げるのを勧める。アイコン自体の見た目は小さくてよい。

### 動き

追従アニメーションを持たない（条件描画のため、開閉は一瞬で切り替わる）。動きを付けたい場合は §3 の常時マウント型に切り替える。

## 3. 半透明のシート（常時マウント型）

常に DOM にあり、`open` の値で `translate-x-0` と画面外（`translate-x-full`）を切り替える。映像・3D・動く背景のように背景そのものを常時描画している画面で、背景を透かしながら滑り込ませたいときに使う。

### 面・覆い・幅・影

| 要素 | クラス | 備考 |
| --- | --- | --- |
| 覆い | `fixed inset-0` ＋主役色相の透過＋わずかな `backdrop-blur` | 覆い自身も `transition-opacity` で開閉に追従させ、`pointer-events` を `open` で出し分ける（閉じている間はクリックを素通りさせる） |
| パネル | `fixed top-0 right-0 h-full w-full sm:w-80` | 640px 未満は全幅、それ以上は 320px |
| 背景を透かす面 | 半透明の面＋`backdrop-blur-xl`＋薄い光の縁（1px） | `foundations/surface-and-depth.md` の glass 面と同じ考え方 |
| 影 | `shadow-overlay` | 別レイヤーとして切り離す |
| 動き | `transition-transform duration-300 motion-reduce:transition-none` | 所要時間をトークンでなく固定値（300ms）で書いているので、`motion-reduce:` の併記が要る（`foundations/motion.md` §3 の方法 3）。トークン経由にすれば併記は不要 |

画面の端に張り付く面なので、セーフエリアをパネルの padding に入れる（ノッチ・ホームインジケーターで内容が隠れない）:
`padding-top: env(safe-area-inset-top, 0px); padding-bottom: env(safe-area-inset-bottom, 0px); padding-right: env(safe-area-inset-right, 0px);`

### 閉じた状態の inert / aria-hidden

常時マウントなので、**閉じている間の状態を明示しないと、見えない要素がタブ順や支援技術に残ってしまう**。

- `aria-hidden`: 開いているときは属性自体を出さない／閉じているときだけ `true` を立てる（両方の状態を同じ属性値で表現しない）。
- `inert`: 閉じている間だけ立てる。`aria-hidden` だけではクリック・タップの遮断までは担保しないため、両方必要。

### Tab トラップ・スクロールロック・フォーカス

- Tab トラップは document 側に張る（`components/modal.md` §3.5 と同じ形）。
- スクロールロックは「開いている間だけ `body` の overflow を退避して固定し、閉じたら戻す」単純な形でもよい。**ただし参照カウント式ではないため、同時に 2 つ以上の面がロックを取り合う画面では背後が動く事故が起きうる**（§5 参照）。
- 開いた瞬間にパネル自身へ `focus()` し、閉じたらトリガーへ戻す。

## 4. 画面端スワイプの帯

画面の左右端に、幅 20px の透明な帯を敷いて水平ジェスチャを拾う。

```
position: fixed; 高さ 100%; 幅 20px; touch-action: pan-y;
```

- **`touch-action: pan-y` が要る理由**: 何もしないと、ブラウザ既定のエッジジェスチャ（戻る操作など）が水平方向の指の動きを先に消費し、しきい値に達する前にジェスチャが打ち切られる。`pan-y` を当てた領域は縦方向だけブラウザに渡し、横方向はページ側が拾える。
- 帯の z-index はドロワー/シート（`z-50`）より下・通常の UI より上（`z-40`）に置く。この帯そのものは何も表示しないタップ不可視領域だが、レイアウト上その 20px には他の操作要素を置かない。
- **判定のしきい値**:
  - 開始位置は画面端から 20px 以内。
  - 水平移動量がある値（例 60px）を超え、かつ「垂直移動量の 2 倍」より大きいときだけ水平ジェスチャと判定する（縦スクロールとの取り合いを避ける）。
  - 開く判定は、**対応する開閉ボタンが表示される画面幅とまったく同じブレークポイント**でだけ有効にする。閾値をずらすと「スワイプでは開くのにボタンが無い/ボタンはあるのにスワイプが効かない」という食い違いが起きる。
- **閉じる判定は開始位置の考え方が違う。** 開くときは「画面端から」だが、閉じるときは「開いているパネルの矩形内から」を起点にする。パネルは画面内にあるので、開くときと同じ「端から」制約を課すと閉じられなくなる。パネルの矩形かどうかは、パネル自身に付けた目印（`data` 属性）を `closest()` で辿って判定し、覆い側は対象に含めない（覆いはタップで閉じる別経路に任せる）。
- **他のモーダル・ダイアログが開いている間は、この帯の「開く」判定自体を無効にする。** モーダルは全画面を覆うため、画面端の 20px もモーダルの一部になっている。ここで判定してしまうと、モーダルの背後でドロワーが開いてしまう。「今 `role="dialog"` の要素が DOM にあるか」で判定すると、覆い要素（`role="dialog"` を持たない）越しのジェスチャも正しく弾ける。**常時マウント型のシート（§3）は閉じていても `role="dialog"` のまま DOM に残る**ので、同じ画面で併用するなら `document.querySelector('[role="dialog"]:not([inert])')` のように閉じた面を除く（除かないと、閉じたシートに一致して一切開けなくなる）。
- 帯の内側に横スクロールする要素（`overflow-x: auto` 等）がある場合、そのジェスチャは丸ごとスワイプ判定から外す（横スクロールを奪わないため）。

## 5. 落とし穴

- **常時マウント型を作ったのに、閉じた状態の `inert` / `aria-hidden` を付け忘れる。** 見た目は隠れていても、キーボード操作・スクリーンリーダーからは開いているのと同じに触れてしまう。
- **スクロールロックの実装方式を画面内で混在させる。** 「参照カウント式」「単純な退避/復元」「画面側が常時固定」の 3 通りが共存できてしまうため、新しい面を足すときにどの前提に乗っているかを確認しないまま実装すると、重ねたときに背後が動く／ロックが解除されないまま残る、のどちらかの事故につながる。
- **スワイプの開始判定を「画面端から」で閉じる方向にも使う。** パネルは画面内にあるので、この条件では閉じられない。開始領域の基準を開閉で分ける。
- **エッジスワイプの帯に `touch-action` を当て忘れる。** ブラウザ既定のジェスチャに先取りされ、しきい値まで届かない。
- **開く判定のしきい値と、対応するボタンの表示ブレークポイントをずらす。** ジェスチャとボタンの片方だけが有効な画面幅が生まれ、挙動の説明が付かなくなる。
- **モーダルが開いているかどうかを見ずにエッジスワイプを許可する。** モーダルの背後でドロワーが開き、閉じたときに想定外の状態が残る。

## 6. チェックリスト

- [ ] 追従アニメーションの要否で、条件描画型／常時マウント型のどちらにするかを決めた
- [ ] 常時マウント型なら、閉じている間 `inert` と `aria-hidden` の両方を立てている
- [ ] 閉じるボタンは画面の物理的な端の反対側に置き、タップ領域は 40px 以上（端に張り付く面では 44px を推奨）
- [ ] フォーカスの記憶と復帰ができ、トリガーが無い（タッチで開いた）場合の代替復帰先もある
- [ ] スクロールロックの方式（参照カウント／単純な退避・復元／画面側で固定）を把握し、他の面と重ねても壊れないことを確認した
- [ ] エッジスワイプは `touch-action: pan-y`・縦横比の判定・対応ボタンと同じブレークポイントを持つ
- [ ] モーダルが開いている間はエッジスワイプの「開く」判定が無効になる
- [ ] `prefers-reduced-motion` で動きが止まることを確認した（常時マウント型のみ）
