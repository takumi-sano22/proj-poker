# モーダル（基底ダイアログの一式）

> **いつ読むか**: モーダル・ダイアログ・確認画面・入れ子の確認ダイアログを作るとき
> **前提**: `foundations/surface-and-depth.md`（影 `overlay` 段・面のレシピ L4）、`foundations/motion.md`（所要時間トークン・reduced-motion の止め方）
> 形の値（幅・余白・角丸・z-index）はそのまま再現してよい。色は役割名で書いてある。

## 1. 要点

- モーダルは **1 つの基底コンポーネント**に、描画（覆い・パネル・見出し/本文/操作の 3 段）と振る舞い（Esc・外側クリック・初期フォーカス・フォーカス復帰・Tab トラップ・スクロールロック）を集約する。呼び出し側は文言と中身だけを渡す。
- **Esc・Tab トラップは document へ張る。** パネル要素に張ると、再描画でフォーカス中の要素が消えたときに拾えない。
- **開いているモーダルはスタックで管理し、最前面の 1 枚だけが Esc・Tab を処理する。** 重なったときに全部が同時に閉じる事故を防ぐ。
- スクロールロックは **参照カウント**で持つ。単純な退避/復元だと、重なったモーダルの内側を閉じた瞬間に背後がスクロール可能に戻ってしまう。
- **サイズは決め打ちの段（sm〜2xl）から選ぶだけにし、呼び出し側で幅を上書きしない。** 幅が要る画面は段を増やす。
- 取り消せない操作の確認では、初期フォーカスを既定（先頭のフォーカス可能要素）に任せず、安全な選択肢へ明示的に向ける。

## 2. 描画（外枠・パネル）

### 2.1 描画方式

- **この基底は portal を使わず、呼び出した場所にそのまま描画する**（`ReactDOM.createPortal` を使わない）。最も単純で、呼び出し側の React コンテキストもそのまま使える。
  ただし `position: fixed` は、祖先に `transform` / `filter` / `backdrop-filter` があるとその祖先が基準になり、画面からずれる（半透明の面で `backdrop-blur` を使う画面は特に踏みやすい）。そういう祖先を持つ画面（アニメーションする容器・別ウィンドウに切り出した面など）で使うなら portal 化を検討する（§7）。

### 2.2 覆い（overlay）

```
fixed inset-0 z-50 flex items-center justify-center p-4 backdrop-blur-sm
```

| 状況 | 背景 | なぜ分けるか |
| --- | --- | --- |
| 不透明な面（solid）の上 | `scrim`（`ink-900` の透過。`foundations/color-usage.md` 参照） | 中立な暗さで地と切り離す |
| 背景を透かす面（glass）の上 | `brand-900` の透過（同系色） | 背景の主役やシーンが透けて見える状態では、無彩色の覆いより背景の色相に寄せた覆いのほうが馴染む |

余白 `p-4`（16px）は画面端とパネルの間の最小ガター。`backdrop-blur-sm` で背後をわずかにぼかし、覆いの下に何かが動いていても気が散らない。

### 2.3 パネル

- 角丸は `rounded-modal`（20px）・影は `shadow-overlay`（`foundations/surface-and-depth.md` L4）で固定する。
- 不透明な面（solid）の上では、面を 2 種類から選ぶ。**新しく作るモーダルは `flat`（面のレシピ L4）にする。** `gradient` は、面のレシピを決める前からある画面の見た目を変えないために残した互換用の既定値:

| 面 | クラス | 用途 |
| --- | --- | --- |
| flat（新規はこちら） | `border border-border-strong bg-surface-raised` | 別レイヤー（`foundations/surface-and-depth.md` の L4）。最前面を最も明るい単色にして背後から切り離す |
| gradient（互換用の既定） | `border border-border bg-surface-gradient inset-shadow-edge` | 既存画面の見た目を変えないため既定値に残している。新規では選ばない |

- 背景を透かす面（glass）は上の 2 種の影響を受けず、常に 1 種類: `border border-brand-200/60（薄い光の縁） bg-surface-raised/85 backdrop-blur-xl`。
- 見出しの文字色も面で変える（不透明面は `on-surface`・透かす面は主役色相を一段濃くした文字色）。

### 2.4 サイズの段

| 段 | 実際の上限 | Tailwind | px |
| --- | --- | --- | --- |
| sm | 24rem | `max-w-sm` | 384px |
| md（既定） | 28rem | `max-w-md` | 448px |
| compact | 32rem | `max-w-lg` | 512px |
| lg | 42rem | `max-w-2xl` | 672px |
| xl | 56rem | `max-w-4xl` | 896px |
| 2xl | 72rem | `max-w-6xl` | 1152px |

- **段の名前は「見た目の大きい順」であって、Tailwind 自身の `max-w` 系ユーティリティの名前と対応しない**（`lg` 段の実体が Tailwind の `max-w-2xl` になっている等）。段を増やすときは、既存の Tailwind クラス命名につられて位置を決めない。
- **呼び出し側で独自の `max-w` 系ユーティリティを当てる逃げ道を作らない。** 個別に上書きできると、画面ごとに違う値が積み重なり、後から見て「なぜこの画面だけ幅が違うのか」が分からなくなる。幅が足りない場面が出たら、段そのものを増やす。

### 2.5 固定高さ（`fixedHeight`）

章タブ・アコーディオンなど中身の量が状態で変わる場面では、既定（パネル自身が `overflow-y-auto` を持ち `max-h-[85vh]` で頭打ちする）のままだと、状態が変わるたびにパネルの高さが伸び縮みしてしまう。

- 呼び出し側は `min(<px>, <vh>)` の形の文字列（例 `min(820px, 90vh)`）を渡す。渡すと次の 3 点が同時に切り替わる。
  1. パネルに `height` を与え、`max-h-[85vh]` の上限クラスは**外す**
  2. パネルを縦並びの flex にし、パネル自身の `overflow-y-auto` は外す
  3. ヘッダー/フッターは伸縮しない固定領域にし、**本文スロットだけ**を `flex-1 overflow-y-auto min-h-0` にする
- **`min()` の 2 引数は必ず両方渡す。** px 単独で渡すと、①の「上限クラスを外す」がそのまま効いてしまい、小さい画面でパネルが画面をはみ出す（実際にこの高さがそのままパネル高になるとは限らないので、目標値は実機で確認して決める）。
- `min-h-0` が無いと、flex の子要素は中身の分だけ伸びてしまいスクロールが起きない。

### 2.6 ヘッダー / 本文 / フッター

| 部位 | 余白 | 境界 |
| --- | --- | --- |
| ヘッダー | `px-6 pb-3 pt-5`（左右 24px・下 12px・上 20px） | 下側に 1px の境界線（面が不透明なら `border`、透かす面なら薄い光の縁） |
| 本文 | `p-4`（16px。固定高のときは `flex-1 overflow-y-auto min-h-0 p-4`） | なし |
| フッター（任意） | `px-4 py-3`（左右 16px・上下 12px） | 上側に境界線（ヘッダーと同じ色） |

見出しの右側に、補助情報（進捗表示など）と閉じるボタンをこの順で並べる領域を用意する。

### 2.7 閉じるボタン

- `rounded-control`（操作要素の角丸）・内側余白 `p-1.5`・アイコン `w-5 h-5`（20px）。hover で沈める面色に切り替え、`duration-quick` / `ease-standard`（`foundations/motion.md`）で遷移する。
- **押せる範囲（20px＋余白 6px × 2 ＝ 32px）は、アイコンだけのボタンの下限 40px（`foundations/type-space-radius.md`）に届かない。** 新しく作るなら `p-2.5`（40px）にするか、ドロワー（`drawer-and-sheet.md`）のように `min-h-[44px] min-w-[44px]` を明示する。

## 3. 振る舞い

### 3.1 Esc

- 開いているモーダルは配列（スタック）に積む。Esc は**スタックの最後尾（＝最前面）と一致するモーダルだけ**が処理する。
- 順序は「**自分が最前面か確かめる → `preventDefault()` → 閉じてよいか（後述 3.2 の `dismissible`）を見る**」。`dismissible` を `preventDefault()` より先に見ない。モーダルが最前面である以上、閉じない設定でも「背後にあるもっと優先度の低い Esc ハンドラ（生成中のキャンセル等）」には落とさないため、専有した事実を先に確定させる。
- **`preventDefault()` は伝播を止めない。** 専有を成り立たせるのは、背後のハンドラ側の約束とセットにしたとき:
  - モーダルの Esc は `document` に、優先度の低いグローバルな Esc（生成のキャンセル等）は `window` に登録する（bubble では `document` の次に `window` へ届くので、モーダルの処理が先に走る）
  - 背後のハンドラは `if (e.defaultPrevented) return;` で降りる（`foundations/contrast-and-a11y.md` §9 の条件 2）
  - モーダルより**先に**走るハンドラ（同じ `document` に先に登録されたもの・capture のもの）には効かないので、そちらは「モーダルが開いているか」を自分で確かめる
  - 基底に `stopPropagation()` を足して解決しない。同じ `document` の他のハンドラ（ドロワーの Esc 等）まで止まり、既存の全モーダルの挙動が変わる。約束を守れないハンドラが混ざる画面では、最前面だけに配信する共有のディスパッチャを作る
- 同意必須のように閉じる手段を持たせたくないモーダルは、`dismissible=false` 相当のフラグで Esc・外側クリックの 2 経路だけを塞ぐ。スタック登録・スクロールロック・フォーカストラップは通常どおり効かせる。

### 3.2 外側クリック

- 覆い（overlay）に `onClick` でクローズを割り当て、パネル側は `onClick` で `stopPropagation()` する。これだけでパネル内クリックが素通りしない。
- 3.1 と同じフラグで、閉じない設定のときは覆いの `onClick` 自体を渡さない。

### 3.3 初期フォーカスの順

1. 呼び出し側が明示した要素（例: 「戻る」ボタン）
2. 無ければパネル内で最初に見つかったフォーカス可能要素
3. 操作要素が 1 つも無い本文だけのモーダルでは、パネル自身（`tabIndex="-1"`）をフォールバック先にする

### 3.4 フォーカスの復帰

開いた瞬間の `document.activeElement` を覚えておき、閉じたらそこへ `focus()` する（WAI-ARIA の dialog パターン）。
基底がやるのはここまで。開いた時点のフォーカスが `body` だった（トリガーを経由せずに開いた等）ときに主要な入力欄へ戻したいなら、
それは呼び出し側の閉じる処理で行う（基底は画面の主役を知らないため）。

### 3.5 Tab トラップ

- keydown リスナーは **document** に張る。パネルに張ると、フォーカス中の要素が再描画で消えて `document.activeElement` が `body` へ落ちた瞬間にトラップが効かなくなる（レスポンシブでアコーディオンとタブが入れ替わる、などの通常操作で起こる）。
- 対応: 「今の `activeElement` がパネルの外にある」なら、Shift の有無に応じて先頭/末尾へ引き戻す。パネル内で末尾から Tab／先頭から Shift+Tab なら反対の端へ回す。
- **フォーカス可能要素が 0 個のときは Tab を無効化してパネルへ留める。** 素通しすると背後の画面を操作できてしまう。
- 最前面のモーダルだけが処理する（3.1 と同じスタック判定）。
- **背後のパネルを `inert` にしている間はこのトラップを止める。** `inert` な要素はフォーカスを受け取れないのに、トラップは「パネル外＝引き戻す」と誤判定して Tab を空振りさせる。重ねた面（§5）のトラップはその面自身が持つ。Esc は止めない（重ねた面側で「閉じる」ではなく「操作を続ける」という別の意味に転用することがあるため）。

### 3.6 スクロールロック（参照カウント）

```
count === 0 のとき: 元の overflow を退避し、"hidden" にする
count を +1
（閉じるとき）count を -1、0 に戻ったら退避値を書き戻す
```

単純な「開いたら hidden・閉じたら空文字」だと、モーダルの上に確認ダイアログを重ねて内側だけ閉じた瞬間に、外側がまだ開いているのに背後がスクロールできてしまう。参照カウントなら、外側が残っている限りロックが保たれる。

### 3.7 aria

- パネルに `role="dialog"` `aria-modal="true"`。
- `aria-labelledby` は呼び出し側が id を渡さなければ自動生成する。
- `aria-describedby` は「基底が描く説明文」と「本文側にある要素の id」の両方を指せるようにし、両方あれば空白区切りで並べる（ARIA は複数 id を許す）。開いた瞬間に読み上げさせたい必須の説明文は、本文側 id をここに繋いで確実に拾う。

## 4. 確認・選択モーダルの作法

### 4.1 取り消せない操作の初期フォーカス

DOM 順の先頭（多くの場合ヘッダーの閉じるボタンや破壊的な操作）へ既定の初期フォーカスを委ねると、開いた直後の Enter が意図しない確定操作を叩いてしまう。**取り消せない操作を持つ確認では、初期フォーカスを明示的に「戻る/キャンセル」側へ向ける。** Enter で確定させたい操作がある場合ほど、この指定を忘れやすい。

### 4.2 remount されないステップ切り替え

複数ステップを 1 つのコンポーネントインスタンスで進める（ステップが変わっても unmount/mount しない）実装では、基底の「開いた時に 1 回だけ効く初期フォーカス」には乗れない。ステップが変わったことを検知できる値（そのステップ固有の一覧の参照など）を目印にした専用の `useEffect` を持ち、そのステップの「今の値」に当たる要素へ自前で `focus()` する。

### 4.3 選択肢の巡回とステップ移動

- 選択肢が縦に並ぶ画面は上下キーで巡回する。
- 左右キーは「前の段／次の段」というステップ移動に使う。**フォーカスが編集可能な要素（`input` / `textarea` / `select` / `[contenteditable]` / `role="textbox"` 等）やリンクに乗っているときは奪わない**（文字カーソル移動を優先する）。判定は「今フォーカスしている要素の種類」で行う。
- **ボタンは除外しない。** 一般則（`foundations/contrast-and-a11y.md` §9）でボタンを除外するのは、そのボタン上で ←→ が別の意味（選択肢間の移動など）を持つ場合のため。選択肢間の移動を ↑↓ に一本化したモーダルでは除外理由が無く、除外するとフォーカスが乗る要素（選択肢・前へ・閉じる・パネル）が全部ボタンなので、←→ が事実上効かなくなる。
- 一覧の行をクリックで直接そのステップへ戻れるようにする場合、その行は上下キーの巡回対象に含めない（読む対象であって操作の主対象ではないため）。キーボードだけで到達できる代わりの「戻る」ボタンを別に用意する。

### 4.4 キーヒントの表示条件

`↑↓ で移動・Enter で決定` のようなヒントは、hover 可能でポインタ精度が高い環境（`hover-fine`。`foundations/contrast-and-a11y.md` 参照）でだけ出す。タッチ環境ではそのキー操作ができないため、実行できないヒントを見せない。**実際に効くキーだけを載せる**（巡回対象を広げたら表記も合わせて増やす）。

## 5. 入れ子のモーダル

確認ダイアログ等をモーダルの上にさらに重ねるときは、その面だけ `z-[60]`（基底の覆いは `z-50`）にする。背後のパネルは `inert` にして、フォーカス・支援技術の両方から一時的に遮断する（§3.5）。
**重ねた確認（「閉じると入力が消えます」等）の Esc・外側クリックは、「元のモーダルを閉じる」ではなく「確認を取り消して元の作業に戻る」に割り当てる。** 誤って Esc を押した人が入力を失わずに済む。そのため背後のパネルが `inert` の間も、基底の Esc 処理は止めない（Tab トラップだけ止める）。

## 6. 基底を共有しない場合の写し

デザイン体系そのものを分ける画面（管理画面など、色や面のトークンを共有しない領域）では、見た目の基底コンポーネントを再利用しないことがある。その場合でも、**アクセシビリティに関わる振る舞い一式だけは同じ形で複製する**:

- スクロールロックの参照カウント（モジュール変数のカウンタで退避/復元）
- Tab トラップを document に張る（パネル要素ではなく）
- 初期フォーカス／閉じたらトリガーへ復帰
- Esc で閉じる

見た目（面の色・角丸・影）は Tailwind の既定色や別の値で組んでよい。**スタック管理（最前面だけが Esc を処理する）は、その体系の中で複数のモーダルが同時に開かない前提なら省略してよい**——ただし前提が崩れたら Esc 二重処理が起きるので、その旨をコメントに残す。

## 7. 未実装の推奨

以下はこの基底には無い。足すときの入口として書く（**実装済みではない**）。

- **portal**: transform を持つ祖先の中にモーダルを置く画面が出たら、`position: fixed` が無効化される事故を避けるため portal 化を検討する。
- **入場の演出**: `@starting-style` ＋ transition（`foundations/motion.md` §4）で、覆いのフェードとパネルの小さな移動＋縮小を付けられる。keyframes より reduced-motion の一括停止に乗りやすい。
- **モバイルでのボトムシート化**: 狭い画面では画面下からせり上がるシートに変え、スワイプで閉じられるようにする選択肢がある（`drawer-and-sheet.md` のシート・スワイプ帯と組み合わせる）。
- **動的ビューポート単位（`dvh`）**: モバイルブラウザの URL バー分だけ高さが変わる問題に対応するなら、`vh` を `dvh` に置き換える。
- **セーフエリア**: 画面下端まで伸ばす場合は `env(safe-area-inset-bottom)` を padding に足す。

## 8. 落とし穴

- **Tab トラップをパネル要素に張る。** 再描画でフォーカス中の要素が消えると `body` へ抜け、二度と戻らない。document に張って「パネル外に出たら引き戻す」分岐を必ず持つ。
- **Esc の `preventDefault` を `dismissible` 判定の後に呼ぶ。** 閉じない設定のモーダルが開いている間、背後の別の Esc ハンドラまで動いてしまう。
- **`preventDefault()` だけで Esc を専有できると考える。** 伝播は止まらない。背後のハンドラが `window` 登録＋`defaultPrevented` を見る約束になっていないと、モーダルの裏で生成のキャンセル等が走る。
- **サイズの段の名前を Tailwind の `max-w` 系ユーティリティの名前と同じ意味だと思い込む。** 独自の意味論の段になっていることがある。
- **`fixedHeight` に `vh` の上限を含めずに渡す。** 上限クラスを外す代償を払い忘れ、小さい画面でパネルが画面をはみ出す。
- **確認画面の初期フォーカスを既定に任せる。** DOM 順の先頭（多くは閉じるボタン）に乗り、キーヒントどおり Enter を押すと閉じる/破棄が走る。
- **`inert` にした背後パネルのトラップを止め忘れる。** 重ねた面にフォーカスがあるのに、背後パネルへ引き戻そうとして Tab が空振りする。
