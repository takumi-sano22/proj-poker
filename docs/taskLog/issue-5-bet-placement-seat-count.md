# Issue #5（一部）: 狭い画面の卓の Bet の重なりを、席数 2〜8 人のすべてで直す

## 概要

#101（`issue-5-table-ui-narrow-overlap.md`）の残課題 2 件を、同じ手順で直した（`Refs #5`）。

1. 4・5・7・8 人卓の 375px 以下で、Bet の札が中央（Board・Pot・Street）や席の面と重なる。
2. 320×568 で席と Bet が 4px 重なることがある。

目標は、2〜8 人卓 × 1280×900 / 375×760 / 375×667 / 320×568 で、席・席の札・Bet・Board・Pot・Street・進行ログ・見出しの Button の重なりが 0 であること。裁定ありの Hero 欄の +106px と 320px の Hero 欄の高さは扱わない（残課題のまま）。

## 初期調査

- 前提: main 5d60f71（#101 マージ後）。web は素の CSS（`apps/web/src/styles.css`）。Bet の札（`.bet`）は卓の上に、席の向き（`--dir-x` / `--dir-y`）に `--bet-rx` / `--bet-ry` を掛けた位置へ絶対配置していた（#101 は 6 人卓だけに合わせて `--bet-rx: 11.5%`）。
- 実測の方法は #101 と同じ（Playwright・headless Chromium。リポジトリ外の一時スクリプト）。席数ごとに server を起動し直し（`TABLE_SIZE=2〜8`・RuleBot・`REVIEW_PROVIDER=fake`・`BOT_THINK_DELAY_MS=0`）、4 つの画面幅で Hero の手番ごと・Hand の終了ごとに測る。1 点だけでは席数・額で外れるので、10 Hand ずつ通す。
  - 席の面・席の札・Bet・Board（札の外接矩形）・Pot・Street・結果・進行ログの矩形の交差、操作 Button の中心の `elementFromPoint`、`scrollWidth − innerWidth`。今回、見出し（見出しの文字・Button）も測りに加えた。見出しは箱ではなく中身で測る（箱の余白は卓が少し入ってよい）。
  - 通しの途中で Bust した CPU は席から外れるので、2〜8 人の席数のうち少ない席数の卓も同じ通しで測れる。席数の違う卓も含めて数えている。
- 修正前（main）: 4・5・7・8 人卓の 375×760 / 375×667 / 320×568 の 12 通りで、重なりの組の種類が合計 40（4 人卓 1〜3 種・5 人卓 3〜4 種・7 人卓 3〜4 種・8 人卓 3〜4 種）。2・3・6 人卓は 0（6 人卓の 320×568 は別の通しで 4px の重なりが出ることがあった。#101 の残課題）。1280×900 は全席数で 0。
  - 組の例: 5 人卓の Bet × Pot（45×15）・席の札 × Pot（30×24）・席の札 × Street（30×18）、4 人卓の Bet × Board（52×4）・席 × Board（7×22）、8 人卓の席 × 席（Hero と隣の席。9×75）・Bet × Board（48×19）。
- 根（Bet）: Bet の札を「席と中央の間」に置く方式は、席数によってその間の幅・高さが変わる（真横に席が来る 4・8 人、斜めの席が中央に近い 5・7 人）ので、席数を足すたびに別の組が重なる。席数ごとに半径を決める方法は、額・Chip の数で札の幅が変わるので収まらない。

## 設計方針

- **狭い画面の Bet の札は、席の面の中（Stack の Chip の下）に置く**（広い画面は従来どおり卓の上）。席に付いて動くので、席数に依らず中央や隣の席と重ならない（重なるとすれば席の面そのもの）。実額は常に出す（BB 換算は補助なので、狭い画面の Bet では省くまま。D49）。`aria-label`（「<名前> のベット <額>」）も同じ。
  - 同じ内容を 2 か所に描かないので、`useNarrowScreen` で 1 か所に決める（#101 と同じ）。
- 席の面が Bet の分だけ高くなると、席は面ごと中心合わせなので、中央側にも同じだけ伸びて中央・隣の席に当たる。そのため、卓を縦に伸ばして席と中央の間を空ける（席数・幅ごとに縦横比を決める）。
- 中央の並べ方を席数で分ける。中央の高さに席の面が来る席数（4・5・7・8 人）は、Street / Board / Pot を縦に積む（Board の札 24px）。ほかの席数（2・3・6 人）は、Board の下に Street と Pot を 1 行に並べる。
- 席の面の幅を抑える: 名前の行（Dealer Button・SB / BB の札）を詰め、Bet の札は幅 76px までで Chip と額を折り返す。7・8 人卓はさらに小さく。
- 既存のトークンと部品だけを使う（新しい色・意匠なし）。

## 判断理由

- Bet を席の面に付けたのは、席数ごとに半径を決める案より、席数・額・Chip の数に依らず「席と中央の間」の幅に頼らないため。席の面が高くなる分は、卓を縦に伸ばして吸収した（ページは縦にスクロールする。Hero 欄が覆う卓の高さは今までどおり、スクロールの先頭だけ）。
- 広い画面は Bet を卓の上に置いたまま（半径 `--bet-rx` 27%・`--bet-ry` 25%）。広い画面は席と中央の間が十分あり、1280×900 の重なりも 0 のため。

## 残課題

- 裁定ありの Hero 欄は、裁定なしより約 106px 高い（375px）。320px の Hero 欄は画面の 7〜9 割を占める。今回は扱っていない（Vocabulary の出し方・Hero 欄の構成の見直し）。
- 狭い画面の卓は縦に長くなった（例: 375px の 5:7 で高さ約 480px、7・8 人卓は 1:2 で約 690px）。7・8 人卓は卓の全体を見るのにスクロールが要る。
